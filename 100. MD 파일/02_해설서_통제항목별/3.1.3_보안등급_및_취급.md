# 3.1.3 보안등급 및 취급

## 인증기준

기밀성, 무결성, 가용성, 법적요구사항 등을 고려하여 자산의 보안등급을 부여하고, 보안등급별 취급 절차에 따라 관리하여야 한다.

<!-- @block name=requirements cols=requirement_set,title id=CI -->

| 구분 | 점검항목 |
|---|---|
| 공통 | 기밀성, 무결성, 가용성, 법적요구사항 등을 고려하여 정보자산의 중요도를 평가하기 위한 기준을 수립하고 있는가? |
| 공통 | 정보자산별로 중요도를 평가하고 각 자산별 특성에 적합한 보안등급을 부여하고 보안등급을 쉽게 확인할 수 있도록 하고 있는가? |
| 공통 | 정보자산의 보안등급에 따른 취급절차(생성, 저장, 이용, 파기 등)를 정의하고 이행하고 있는가? |

## 점검목적

정보자산의 중요도에 기반한 적절한 보호조치를 적용하여 기밀성·무결성·가용성 및 법적 요구사항을 효과적으로 보장한다.

## 점검항목 해설

### 점검항목 1)

<!-- @block name=guidance requirement_no=1 cols=kind,text id=CM -->

| 구분 | 해설 |
|---|---|
| 본문 | 정보자산의 유출, 장애 및 침해 발생 시 조직의 업무에 미치는 영향을 고려하여 식별된 정보자산의 중요도를 평가할 수 있는 기준을 수립하여야 한다. |
| 본문 | 일반적으로 기밀성, 무결성, 가용성, 법적요구사항 등을 고려하여 중요도 평가기준을 마련할 수 있다. 이외에도 서비스 영향, 재무적 손실, 고객 상실, 대외 이미지 등도 추가적으로 고려할 수 있다. |
| 세부 | 정보자산의 중요도 평가 기준 수립 |
| 세부 | 정보자산 중요도 평가 시 타 자산과의 연관성 고려 |
| 주의 | 정보자산 중요도를 평가하기 위한 주요 고려사항 |
| 예시 | ∙ 기밀성 : 정보자산이 접근권한이 없는 자에게 노출되었을 때의 위험성을 파악 |
| 예시 | ∙ 무결성 : 하드웨어 변경, 소프트웨어 변조, 데이터 값 수정 등 정보자산의 상태 또는 내용이 임의로 변경되었을 때의 위험성을 파악 |
| 예시 | ∙ 가용성 : 정보자산이 필요 시 사용이 불가능하거나, 접근이 되지 않을 때 서비스에 미치는 영향을 파악 |
| 예시 | ∙ 법적요구사항 : 해당 자산의 운영과 관련한 법규가 있는지 파악하고, 관련 근거를 준수하지 않았을 때의 위험성 파악 |

### 점검항목 2)

<!-- @block name=guidance requirement_no=2 cols=kind,text id=CM2 -->

| 구분 | 해설 |
|---|---|
| 본문 | 정보자산 중요도 평가기준에 따라 정보자산별로 중요도를 평가하여야 한다. 또한 정보자산별 특성에 따라 보안등급을 부여하고 다음과 같이 임직원이 보안등급을 쉽게 식별할 수 있도록 하여야 한다. |
| 세부 | 중요도 평가 시기: 자산 최초 도입, 역할 및 용도 변경 등 |
| 세부 | (전자)문서 : 기밀(비밀), 대외비, 비공개, 일반 등 등급화하여 표시 |
| 세부 | 서버 등 하드웨어 자산 : 자산번호, 바코드, 태그 표시 등을 통한 보안등급 확인 |
| 주의 | IDC를 임대하여 클라우드서비스를 제공하는 IaaS의 경우 불필요하게 타인에게 보안등급 등이 노출되지 않도록 서버 등 정보자산에 보안등급을 부착하지 않고 자산번호, 바코드 등을 통해 내부자들만 보안등급을 인식할 수 있도록 조치하는 것이 바람직 |

### 점검항목 3)

<!-- @block name=guidance requirement_no=3 cols=kind,text id=CM3 -->

| 구분 | 해설 |
|---|---|
| 본문 | 정보자산의 보안등급에 따라 취급절차(생성, 저장, 이용, 파기 등)를 정의하고 이에 따른 접근통제 등 적절한 보안통제를 이행하여야 한다. |
| 주의 | 정보자산 보안등급에 따른 보안통제 예시 |
| 예시 | ∙ 정보자산 분류 및 중요도 평가기준에 따른 보안등급 평가 |
| 예시 | ∙ 자산 담당자 지정 및 담당자 외의 시스템 접근 제한 등 차등 |
| 예시 | ∙ 데이터 저장·처리·전송 시 인증 및 권한관리, 암호화, 접근통제, 개인정보 마스킹, 접근기록 생성·보관·검토 등 보안등급에 따라 차별된 보안통제 적용 |
| 예시 | ∙ 정보자산 파기 시 저장매체 내의 중요 데이터를 복구 불가능하도록 삭제 등 차등 조치 |

## 부적합 사례

<!-- @block name=findings cols=text id=NC -->

| 부적합 사례 |
|---|
| 사례 1 : 서버 접속용 전용 PC의 경우 타 PC에 비하여 높은 보안통제를 적용하고 있으나, 중요도 평가 시 일반 업무용 PC와 동일하게 평가하는 등 모든 인증범위 내 PC를 동일한 보안등급으로 평가한 경우 |
| 사례 2 : 관련 절차에 정보자산의 보안 등급에 따른 차등적인 보안정책 적용을 규정하고 있으나 중요도가 높은 1등급 서버에 대하여 3등급 서버와 동일한 수준의 보안정책을 적용하고 있는 경우 |
| 사례 3 : 클라우드 환경에서 컨테이너 및 이미지 기반 운영을 하고 있으나, 물리 서버 기준으로만 자산 중요도를 평가하여 Pod, Container, VM 등에 대한 보호 수준이 정책에 반영되지 않은 경우 |
