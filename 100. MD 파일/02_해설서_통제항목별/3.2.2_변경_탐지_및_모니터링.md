# 3.2.2 변경 탐지 및 모니터링

## 인증기준

클라우드컴퓨팅서비스에 사용된 자산(시설, 장비, 소프트웨어 등)의 변경을 지속적으로 모니터링 하여 허가받지 않은 변경을 탐지하고 최신의 변경 이력을 유지하여야 한다.

## 점검목적

자산 변경 사항을 식별·추적하여 무단 변경을 방지하고, 보안 및 서비스 안정성을 지속적으로 확보한다.

## 점검항목 해설

### 점검항목 1)

<!-- @block name=guidance requirement_no=1 cols=kind,text id=CM -->

| 구분 | 해설 |
|---|---|
| 본문 | 클라우드서비스에 사용된 자산(시설, 장비, 소프트웨어 등)에 대해서 최신 변경이력을 유지하여야 한다. |
| 세부 | 변경 전 또는 변경 후 변경 사실을 정보자산 관리 책임자(또는 담당자)에게 통보하는 절차 마련 |
| 세부 | 정보자산 관리 책임자는 주기적으로 정보자산 변경 여부를 조사 수행 |
| 본문 | 중요시스템에 대해서는 보안 모니터링 도구 등을 사용하여 허가받지 않은 변경을 탐지하여야 한다. |
| 세부 | 반입된 기자재 현황, SW설치목록 등을 통해 미승인 변경 사례 점검 |
| 세부 | 허가받지 않은 변경을 탐지할 경우 대응할 수 있는 절차 마련 |

## 부적합 사례

<!-- @block name=findings cols=text id=NC -->

| 부적합 사례 |
|---|
| 사례 1 : 클라우드서비스 관련 자산 변경 시 변경 수행 부서가 정보자산 관리 부서에 이를 통보하는 절차가 없고 정보자산 관리부서가 자산 변경 여부를 정기적으로 점검하는 절차도 마련되어 있지 않은 경우 |
| 사례 2 : 클라우드서비스 관련 서버를 증설하고 해당 부서가 이를 정보자산 담당부서에 통지하였으나, 이를 정보자산 목록에 반영하고 있지 않은 경우 |
| 사례 3 : 내부 규정에 따라 정기적으로 자산 변경 여부를 점검하여야 하나 이를 수행하지 않아 클라우드서비스 관련 서버에 하이퍼바이저 프로그램이 신규 버전으로 업데이트 된 사실을 파악하지 못하고 있는 경우 |
| 사례 4 : 운영자가 승인 없이 컨테이너 이미지 버전을 직접 교체하였으나 변경 탐지 방법 및 절차 등이 없어 식별·관리 할 수 없는 경우 |
