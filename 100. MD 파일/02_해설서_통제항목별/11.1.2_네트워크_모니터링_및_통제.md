# 11.1.2 네트워크 모니터링 및 통제

## 인증기준

DDoS, 비인가 접속 등으로 인한 서비스 중단 및 중요정보 유출 등을 막기 위해 네트워크를 모니터링하고 통제하여야 한다.

## 점검항목

<!-- @block name=requirements cols=requirement_set,title id=CI -->

| 구분 | 점검항목 |
|---|---|
| 공통 | 접근통제 정책에 따라 인가된 사용자만이 내부 네트워크(서비스망, 관리망)에 접근할 수 있도록 네트워크 식별자(IP) 할당 등을 통제하고 있는가? |
| 공통 | 내부 네트워크를 구성하는 주요자산 목록, 구성도, IP 현황을 최신으로 유지하고 안전하게 관리하고 있는가? |
| 공통 | 내부 네트워크 IP 주소는 사설 IP로 할당하고 국제권고표준을 따르고 있는가? |
| 공통 | DDoS, 비인가 접속 등으로 인한 서비스 중단 및 중요정보 유출 등을 예방하기 위해 네트워크를 모니터링하고 있는가? |

## 점검목적

비정상적인 행위를 탐지하고 정보보안 사고의 발생을 신속하게 식별한다.

## 점검항목 해설

### 점검항목 1)

<!-- @block name=guidance requirement_no=1 cols=kind,text id=CM -->

| 구분 | 해설 |
|---|---|
| 본문 | 클라우드서비스 운영에 포함된 자산에 IP를 부여하는 경우 승인절차에 따라 IP를 할당하여야 하며, 승인되지 않은 IP의 경우 접속을 차단하여야 한다. |
| 세부 | 인가된 사용자만 네트워크에 접근할 수 있도록 허용 |
| 세부 | 네트워크 장치에 불필요한 서비스 및 포트 등 제거 또는 차단 |

### 점검항목 2)

<!-- @block name=guidance requirement_no=2 cols=kind,text id=CM2 -->

| 구분 | 해설 |
|---|---|
| 본문 | 내부 네트워크를 구성하는 주요 자산목록, 구성도, IP 현황 등을 최신으로 유지하고, 외부에 유출되지 않도록 대외비 이상으로 안전하게 관리하여야 한다. |
| 세부 | 최소한의 인력만 문서에 접근 가능하도록 통제 |
| 세부 | 전자문서 형태로 관리할 경우 암호 설정 등 |
| 세부 | 정기적인 접근권한 타당성 검토 |
| 세부 | 네트워크 접근이 가능한 모든 IP 식별 |

### 점검항목 3)

<!-- @block name=guidance requirement_no=3 cols=kind,text id=CM3 -->

| 구분 | 해설 |
|---|---|
| 본문 | 관리망의 주소체계는 외부로 라우팅되지 않는 표준에서 정한 사설 IP주소 체계를 사용하고, 내부 주소체계가 외부에 유출되지 않도록 하여야 한다. |
| 세부 | 네트워크별 IP주소 부여 기준 마련 예시 |
| 주의 | 사설 IP주소(RFC 1918) |
| 예시 | ∙ 10.0.0.0 ~ 10.255.255.255 |
| 예시 | ∙ 172.16.0.0 ~ 172.31.255.255 |
| 예시 | ∙ 192.168.0.0 ~ 192.168.255.255 |
| 주의 | IPv4 Link-Local IP(RFC 3927) |
| 예시 | ∙ 169.254.0.0 ~ 169.254.255.255 |

### 점검항목 4)

<!-- @block name=guidance requirement_no=4 cols=kind,text id=CM4 -->

| 구분 | 해설 |
|---|---|
| 본문 | DDoS, 비인가 접속 등의 서비스 중단 및 중요정보 유출 등을 예방하기 위해 네트워크 모니터링 방안을 수립하고 이행하여야 한다. |
| 주의 | 네트워크 관리 및 모니터링 등은 외부 위탁 가능하며, 외부 위탁되는 경우 계약서 또는 SLA 확인 필요 |
| 세부 | 접속기록 및 이벤트 로그 정기 모니터링 |
| 세부 | 의심 활동 탐지 시 자동화된 경보 및 대응 절차 수립 |
| 세부 | 모니터링 로그는 최소 6개월 이상 보관 |

## 부적합 사례

<!-- @block name=findings cols=text id=NC -->

| 부적합 사례 |
|---|
| 사례 1 : 외부로부터 클라우드서비스 네트워크에 대한 침해 시도를 인지할 수 있도록 하는 상시 또는 정기적 모니터링 체계 및 절차를 마련하고 있지 않는 경우 |
| 사례 2 : 네트워크 모니터링 절차에 네트워크 모니터링 시 탐지된 이상 트래픽에 대한 조치 절차가 누락되어 있는 경우 |
| 사례 3 : 내부망에 위치한 데이터베이스 서버 등 일부 중요 서버의 IP주소가 내부 정책·지침과 달리 공인 IP로 설정되어 있고, 네트워크 접근 차단이 적용되어 있지 않은 경우 |
| 사례 4 : 방화벽 정책에 IP를 대역으로 과도하게 허용하고, 알 수 없는 IP에 대해 접근을 허용하거나, 사용하지 않는 port를 허용하고 있는 경우 |
| 사례 5 : 네트워크 보안 통제 적용 여부를 1년 이상 미검토, '네트워크 보안 통제 절차'에서는 반기별로 보안 통제를 검토하도록 하고 있으나, 실제 방화벽 규칙에 통제가 적용되었는지 정기적인 검토 이력이 없고 최근 검토 기록은 3년 전이 마지막이며, 신규 추가된 가상 네트워크 3개는 검토 대상에서 누락된 경우 |
