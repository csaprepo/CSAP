# 11.1.1 네트워크 보안정책 수립

### 점검항목 1)

<!-- @block name=guidance requirement_no=1 cols=kind,text id=CM -->

| 구분 | 해설 |
|---|---|
| 본문 | 네트워크와 네트워크 내부 정보의 보안을 보장하여야 한다. |
| 세부 | 네트워크 분리를 위해 VLAN, VPC, Network Policy 등 기술적 통제를 구현 |
| 세부 | 서로 다른 신뢰 수준의 환경(개발/테스트/운영)을 논리적 또는 물리적으로 분리 |
| 세부 | 네트워크 트래픽 모니터링 및 이상 징후 탐지 |
| 세부 | 네트워크 분리, 암호화 통신, 접근통제, 모니터링 등을 포함하는 네트워크 보안 정책을 수립하고 분기 1회 이상 검토 |
| 세부 | 정책은 네트워크 분리, 암호화 통신, 접근통제, 모니터링을 포함 |
| 세부 | 클라우드 환경에서 기술적 통제(VPC, Security Group, Network Policy 등)를 구현 |
| 본문 | 내부망을 통해 클라우드시스템에 접속하는 경우 지정된 단말을 통해서만 접근할 수 있도록 통제하여야 한다. |
| 세부 | 스마트패드, 스마트폰 등 스마트기기를 통한 클라우드시스템 원격운영 금지 |
| 세부 | 무선 네트워크 사용에 대한 제한 사항 |
| 세부 | 네트워크 관리용 단말의 접근통제 절차(IP나 MAC 통제 방법, 단말의 수 등) |
| 세부 | 네트워크 관리용 단말의 운영절차(백신 설치, 최신 보안패치, 불필요한 프로그램 제거, 식별 및 인증 수행 등) |
| 세부 | IP 할당 절차 등 |
| 세부 | 계정별 사용현황 현행화 및 정기 검토 |
| 세부 | 네트워크 사용 단말기 목록 관리 |
| 본문 | 외부 네트워크를 통한 시스템 원격운영은 원칙적으로 금지하여야 한다. |
| 세부 | 단 긴급 장애대응 등과 같이 부득이한 경우 보안대책 마련 |
| 세부 | ∙ 최고책임자의 승인 |
| 세부 | ∙ 접속 단말 및 사용자 인증 (IP/MAC인증, 2-Factor 인증 등) |
| 세부 | ∙ 한시적 접근권한 부여 |
| 세부 | ∙ 원격으로 접근하는 채널에 대한 보호 대책(VPN 사용, SSH 사용 등) |
| 세부 | ∙ 접속 단말 보안 |
| 세부 | ∙ 원격 운영 현황 모니터링 |
| 세부 | ∙ 원격 접속에 대한 로깅 및 주기적 분석 |
| 세부 | ∙ 원격운영 관련 보안인식 교육 등 |
| 세부 | ∙ 접속 위치 제한 : 접근가능 위치 제한, 접속자 특정 IP주소 할당 |
| 세부 | ∙ 외부에서 시스템 접속 시 관리자 전용 페이지 접근 제한 |

## 부적합 사례

<!-- @block name=findings cols=text id=NC -->

| 부적합 사례 |
|---|
| 사례 1 : 내부 서버팜이 구성되어 있으나, 네트워크 접근제어 설정 미흡으로 내부망에서 서버팜으로의 접근이 과도하게 허용되어 있는 경우 |
| 사례 2 : 외부자(외부 개발자, 방문자 등)에게 제공되는 네트워크를 별도의 통제 없이 내부 업무 네트워크와 분리하지 않은 경우 |
| 사례 3 : 내부 정책·지침과는 달리 MAC주소 인증, 필수 보안 소프트웨어 설치 등의 보호대책을 적용하지 않은 상태로 네트워크 케이블 연결만으로 사내 네트워크에 접근 및 이용할 수 있는 경우 |
| 사례 4 : 내부 정책·지침에는 클라우드시스템에 대한 원격 접근은 원칙적으로 금지하고 불가피한 경우 IP 기반의 접근통제를 통하여 승인된 사용자만 접근할 수 있도록 명시하고 있으나, 클라우드시스템에 대한 접근통제 IP주소가 설정되어 있지 않아 모든 PC에서 원격 접속이 가능한 경우 |
| 사례 5 : 네트워크 보안 정책 문서 미수립, 방화벽 보안 룰셋을 운영 중이나, '네트워크 보안 정책' 문서가 존재하지 않음. 담당자 개인 판단으로 방화벽 규칙을 설정하고 있으며, 정책 승인 및 검토 프로세스가 없는 경우 |
