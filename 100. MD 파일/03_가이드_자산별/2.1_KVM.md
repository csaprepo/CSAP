## GUIDE-KVM-001 불필요한 계정 제거

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-KVM-001 |
| 플랫폼 | KVM |
| 점검영역 | 보안 설정 |

### 항목 설명

로그인이 가능한 사용하지 않는 불필요한 계정(퇴직, 전직 등의 이유로 사용하지 않는 계정 및 장기간 미사용 계정, 테스트, default 계정)은 사용 중인 계정보다 상대적으로 관리가 잘 이루어지지 않아 공격자의 목표가 되어 계정이 탈취될 수 있으므로 시스템 계정 중 불필요한 계정 및 default 계정은 제거해야 한다. 또한 default 계정의 경우 비인가자가 접근할 수 있으므로 제거 또는 변경이 필요하다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 불필요한 계정이 존재하지 않는 경우 |
| 취약 조건 | 불필요한 계정이 존재하는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • 불필요한 계정 및 의심스러운 계정 존재 여부 확인 |
| 2 | # grep /bin/bash /etc/passwd &#124; cut –f1 –d: |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 사용하지 않는 default 계정 확인 |
| 2 | 1) 담당자가 해당 계정의 용도를 명확하게 알지 못하는 경우 |
| 3 | 2) 테스트 계정 |
| 4 | 3) 퇴직자 계정 |
| 5 | 4) 인가되지 않은 계정 |

<!-- @code id=CMD-001 block=check_steps language=sh -->

```sh
grep /bin/bash /etc/passwd | cut -f1 -d:
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • 계정 삭제 |
| 2 | 1) 계정 목록 확인 후, 불필요한 계정(인가되지 않은 계정, 퇴직자 계정, 테스트 계정 등 담당자가 실제 업무에 필요 없다고 판단하는 계정)은 삭제 또는 잠금/만료 설정 |

### 비고

※ 담당자와의 인터뷰를 통해 담당자가 업무에 필요 없다고 판단하는 계정을 파악하여 불필요한 계정 및 의심스러운 계정을 제거

## GUIDE-KVM-002 Session Timeout 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-KVM-002 |
| 플랫폼 | KVM |
| 점검영역 | 보안 설정 |

### 항목 설명

관리자가 실수로 로그 아웃을 하지 않고 자리를 비우는 경우 비인가자가 해당 장비에 접근하여 침해 사고를 일으킬 위험이 존재한다. 따라서 관리자가 장비에 접속하고 무의식적으로 장기간 접속 터미널을 사용하지 않을 때 자동으로 접속을 종료하거나 로그 아웃이 되도록 설정해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | Session Timeout이 10분(600초) 이내로 설정되어 있는 경우 |
| 취약 조건 | Session Timeout이 10분(600초) 이내로 설정되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • Session Timeout 설정 정보 확인 |
| 2 | $ cat /etc/profile &#124; grep TMOUT |

<!-- @code id=CMD-002 block=check_steps language=sh -->

```sh
cat /etc/profile | grep TMOUT
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • Sesstion Timeout 설정 |
| 2 | 1) $ vi /etc/profile |
| 3 | 2) readonly TMOUT=600; |
| 4 | export TMOUT |

<!-- @block name=remediation method_no=2 cols=step,text id=RM2-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 설정 적용 |
| 2 | 1) source /etc/profile |

## GUIDE-KVM-003 IP 접근 제한 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-KVM-003 |
| 플랫폼 | KVM |
| 점검영역 | 보안 설정 |

### 항목 설명

취약한 네트워크 서비스(Telnet, FTP)를 통한 외부 비인가자의 불법적인 시스템 침해 사고를 방지하기 위해 iptables을 이용하여 허용 호스트만 서비스를 사용할 수 있도록 IP 주소 및 포트 번호를 제한해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 접속을 허용할 특정 호스트에 대한 IP 주소 및 포트 번호를 제한하고 있는 경우 |
| 취약 조건 | 접속을 허용할 특정 호스트에 대한 IP 주소 및 포트 번호를 제한하고 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • iptables 설정 확인(Ubuntu) |
| 2 | # iptables –L –n –v |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT3-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • iptables 설정 확인(CentOS) |
| 2 | # iptables –t –nat –L |

<!-- @block name=check_steps method_no=3 cols=step,text id=MT3-3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • ssh telnet 등 포트 포워딩 설정 확인 |
| 2 | # iptables –L FORWARD |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • iptables 기본 정책을 DROP 설정 후, 접근 허용 IP 등록 |
| 2 | 1) iptables –P 명령어를 입력하여 기본 정책 변경(DROP) |
| 3 | # iptables –P INPUT DROP |
| 4 | 2) iptables –A 명령어를 입력하여 특정 서비스에 대한 접근 허용 IP 등록 |
| 5 | # iptables –A INPUT –p tcp –s [접근 허용 IP] --dport [포트 번호] -j ACCEPT |
| 6 | 3) 설정 내용 저장 |
| 7 | # service iptables save |

## GUIDE-KVM-004 Default Bridge 제거

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK4 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-KVM-004 |
| 플랫폼 | KVM |
| 점검영역 | 보안 설정 |

### 항목 설명

Default 네트워크 Bridge의 동일한 호스트에서 네트워크 통신 제한이 되지 않으므로 네트워크 공격에 취약하다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | Default Bridge를 사용하고 있지 않고 별도의 네트워크 bridge를 사용하는 경우 |
| 취약 조건 | Default Bridge를 사용하고 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 명령어를 입력하여 Default Bridge 사용 확인 |
| 2 | 1) # virsh net-list |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • Default Bridge 제거 후, 별도 네트워크 브릿지 생성하여 사용 |
| 2 | 1) virsh net-destroy default |
| 3 | 2) virsh net-undefine default |
| 4 | 3) service libvirtd restart |

### 비고

※ KVM 설치 시, Default Bridge 자동 생성 ※ Default Bridge가 출력되지 않는다면 Default Bridge ‘사용 안함‘ 설정

## GUIDE-KVM-005 로그의 정기적 관리 및 백업

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-KVM-005 |
| 플랫폼 | KVM |
| 점검영역 | 보안 설정 |

### 항목 설명

로그 정보는 침해 사고 발생 시 해킹의 흔적 및 공격기법을 확인할 수 있는 중요 자료로 이용될 수 있으며 정기적인 로그 분석을 통하여 시스템 침입 흔적과 취약점을 확인할 수 있다. 정기적인 로그 점검을 통해 안정적인 시스템 상태를 유지하고 침해 사고 시 외부 공격 여부를 파악하고 대처해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 로그를 기록하고 있으며 로그 파일 백업이 정기적으로 이루어지고 있는 경우 |
| 취약 조건 | 로그를 기록하고 있으며 로그 파일 백업이 정기적으로 이루어지고 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 인터뷰를 통해 로그 기록 정책 확인 |
| 2 | 1) 로그 기록 방식 |
| 3 | 2) 로그 파일 기록 주기 |
| 4 | 3) 로그 파일 백업 방식 및 주기 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 로그 기록 및 백업 |
| 2 | 1) 로그를 기록하고 있지 않을 경우 |
| 3 | 로그 기록 및 백업 정책을 세워 로그를 주기적으로 남겨야 하며 로그 파일 또한 주기적으로 백업을 진행해야 함 |

### 비고

※ su 시도에 관한 로그: /var/log/sulog, /var/log/secure 반복적인 로그인 실패에 관한 로그: /var/log/btmp 로그인 거부 메시지에 관한 로그: /var/log/messages

## GUIDE-KVM-006 최신 보안 패치 적용

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK6 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-KVM-006 |
| 플랫폼 | KVM |
| 점검영역 | 보안 설정 |

### 항목 설명

주기적인 패치 적용을 통하여 보안성 및 시스템 안전성을 확보하는 것이 시스템 운용의 중요한 요소이다. 서비스 중인 시스템의 경우 패치 적용에 따르는 문제점(현재 운용 중인 응용프로그램의 예기치 않은 중지, 패치 자체의 버그 등)과 재부팅의 어려움 등으로 많은 패치를 적용하는 것이 매우 어렵기 때문에 패치 적용시 많은 부분을 고려해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR6 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 최신 보안 패치 적용 정책을 수립하여 주기적으로 패치를 관리하고 있는 경우 |
| 취약 조건 | 최신 보안 패치 적용 정책을 수립하지 않고 주기적으로 패치 관리를 하지 않는 경우 |

| 4 | 3) virsh version —daemon |
