## GUIDE-XEN-001 Default 계정 관리

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-XEN-001 |
| 플랫폼 | Xenserver |
| 점검영역 | 계정 관리 |

### 항목 설명

시스템에서 이용하지 않는 Default 계정 및 의심스러운 특이한 계정의 존재 여부를 검사하여 삭제한다. 대부분 시스템에서 사용하지 않는 것이 확실한 아래의 계정들과 의심스러운 계정을 삭제하여 일반적으로 로그인이 필요치 않은 시스템 계정은 로그인을 금지한다. OS나 Package 설치 시 Default로 생성되는 계정은 대부분 Default 패스워드를 사용하는 경우가 많으며 패스워드 추측 공격에 악용될 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | OS 나 Package 설치 시 기본으로 생성되는 불필요한 계정이 존재하지 않을 경우 |
| 취약 조건 | OS 나 Package 설치 시 기본으로 생성되는 불필요한 계정이 존재할 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • lp, uucp, nuucp 의심스러운 특이한 계정(예. guest, test) 및 미사용 계정의 존재 여부 확인 |
| 2 | # cat /etc/passwd &#124; egrep "lp:&#124;uucp:&#124;nuucp:“ |
| 3 | ※ 퇴직, 휴직, 계약 해지자 등 해당 계정 존재 시 삭제 |
| 4 | ※ lp, uucp, nuucp, 의심스러운 특이한 계정(예. guest, test) 및 미사용 계정 삭제 |

<!-- @code id=CMD-001 block=check_steps language=sh -->

```sh
cat /etc/passwd | egrep "lp:|uucp:|nuucp:"
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • 불필요한 계정 삭제 |
| 2 | # userdel lp |
| 3 | # userdel uucp |
| 4 | # userdel nuucp |
| 5 | ※ 로그인 쉘을 /bin/false로 수정하는 것은 보안상 문제가 발생할 수 있으므로 삭제를 권고함 |
| 6 | ※ /nologin 설정은 양호로 처리함 |

## GUIDE-XEN-002 일반계정 root 권한 관리

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-XEN-002 |
| 플랫폼 | Xenserver |
| 점검영역 | 계정 관리 |

### 항목 설명

시스템 관리자는 root 계정을 포함해, 모든 계정의 의심되는 디렉터리 및 파일을 정기적으로 조사하여 삭제하며, 주기적으로 불필요한 사용자 계정을 조사하여 제거하는 것이 보안상 필요하다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | root 및 시스템 계정(daemon, bin, adm, uucp, nuucp, lp, hpdb 등)을 제외하고 UID가 0이 존재하지 않는 경우 |
| 취약 조건 | root 및 시스템 계정(daemon, bin, adm, uucp, nuucp, lp, hpdb 등)을 제외하고 UID가 0이 존재하는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • /etc/passwd 파일의 필드 3번째 값 확인(UID가 0인지 확인) |
| 2 | # cat /etc/passwd |
| 3 | (예시) test:x:0:0:test:/home/test:/bin/bash |
| 4 | ※ UID가 0일 경우 취약함 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • root 및 시스템 계정 외 UID가 0인 계정의 UID 값 변경 |
| 2 | (예시) test 계정의 UID 를 2002로 바꿀 경우 |
| 3 | # usermod -u 2002 test |

## GUIDE-XEN-003 passwd 파일 권한 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-XEN-003 |
| 플랫폼 | Xenserver |
| 점검영역 | 계정 관리 |

### 항목 설명

“/etc/passwd” 파일의 접근 권한을 제한하고 있는지 점검하며, 파일 설정의 문제점이나 파일 permission 등을 진단하여 관리자의 실수나, 오류로 발생할 수 있는 침해사고(일반 사용자 권한 /root 권한 획득)의 위험성을 진단한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 패스워드 파일의 소유자가 root이고, 권한이 644(rw-r--r--)인 경우 |
| 취약 조건 | 패스워드 파일의 소유자가 root가 아니거나 타 사용자에게 쓰기 권한 및 접근 권한이 존재할 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • /etc/passwd 파일의 접근권한 확인 |
| 2 | # ls –al /etc/passwd |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • /etc/passwd 파일의 권한 변경 |
| 2 | # chmod 644 /etc/passwd |
| 3 | # chown root /etc/passwd |

## GUIDE-XEN-004 group 파일 권한 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK4 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-XEN-004 |
| 플랫폼 | Xenserver |
| 점검영역 | 계정 관리 |

### 항목 설명

Group 파일을 일반 사용자가 접근하여 변조하게 되면 인가되지 않은 사용자가 root 그룹으로 등록되어 root 권한 획득이 가능하다. Group 파일을 일반 사용자들이 수정할 수 없도록 제한하고 있는지 점검하여 타 사용자의 쓰기 권한을 제한해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | /etc/group 파일의 소유자가 root(또는 bin)이고 권한이 644(rw-r--r--)인 경우 |
| 취약 조건 | /etc/group 파일의 소유자가 root(또는 bin)가 아니거나 타 사용자에게 쓰기 권한 및 접근 권한이 존재할 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • /etc/group 파일의 접근 권한 확인 |
| 2 | # ls –al /etc/group |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • /etc/group 파일의 권한 변경 |
| 2 | # chmod 644 /etc/group |
| 3 | # chown root /etc/group |

## GUIDE-XEN-005 패스워드 사용규칙 적용

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-XEN-005 |
| 플랫폼 | Xenserver |
| 점검영역 | 계정 관리 |

### 항목 설명

패스워드 추측 공격을 피하고자 패스워드 최소길이가 설정되어 있는지 점검한다. 패스워드 최소길이가 설정되어 있지 않거나 짧게 설정된 경우, 악의적인 사용자가 패스워드를 쉽게 유추할 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 패스워드 정책에 따른 설정이 적용된 경우 |
| 취약 조건 | 패스워드 정책에 따라 설정이 적용되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 패스워드 최소길이, 최소 사용 기간, 최대 사용 기간 설정 확인 (단위: 일) |
| 2 | # cat /etc/login.defs &#124; grep -i "PASS_MAX_DAYS" |
| 3 | # cat /etc/login.defs &#124; grep -i "PASS_MIN_DAYS" |
| 4 | # cat /etc/login.defs &#124; grep –i "PASS_MIN_LEN“ |

<!-- @code id=CMD-002 block=check_steps language=sh -->

```sh
cat /etc/login.defs | grep -i "PASS_MAX_DAYS"
cat /etc/login.defs | grep -i "PASS_MIN_DAYS"
cat /etc/login.defs | grep -i "PASS_MIN_LEN"
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • /etc/login.defs에서 아래와 같은 설정으로 변경 (단위: 일) |
| 2 | #vi /etc/login.defs |
| 3 | PASS_MIN_LEN 8 |

| 플랫폼 | Xenserver |
| 점검영역 | 파일 시스템 |

### 항목 설명

root 계정의 PATH 환경변수에 ”.“ (현재 디렉터리 지칭)가 포함되어 있으면, root 계정의 인가자로 인해 비의도적으로 현재 디렉터리에 있는 명령어가 실행될 수 있다. 즉 ”.“이 /usr/bin이나 /bin, /sbin 등 명령어들이 있는 디렉터리보다 우선하여 있을 경우, root 계정의 인가자가 어떠한 명령을 실행했을 때, 비인가자가 불법적으로 위치시킨 파일을 비의도적으로 실행하여, 예기치 않은 결과를 가져올 수 있다. 또한 ”.“ 뿐만 아니라 비인가자가 불법적으로 생성한 디렉터리가 먼저 선택되어 예기치 않은 결과를 가져올 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR17 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 현재 위치를 의미하는 ”.“이 없거나, PATH 맨 뒤에 존재하는 경우 |
| 취약 조건 | 현재 위치를 의미하는 ”.“이 앞이나 중간에 존재하는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT17 -->

| 순서 | 절차 |
|---:|---|
| 1 | • PATH 설정 확인 |

<!-- @block name=remediation method_no=1 cols=step,text id=RM17 -->

| 순서 | 절차 |
|---:|---|
| 1 | • root 계정의 환경변수 설정파일(.profile, .cshrc등)과 ”/etc/profile“ 등에서 PATH 환경변수에 포함된 현재 디렉터리를 나타내는 ”.“을 제거 |

## GUIDE-XEN-030 syslog 전송 포트 차단

### 점검 정보

| 점검영역 | 패치 및 로그 관리 |

### 항목 설명

UDP 514 Port는 Remote로 syslog를 전송하는 Port로 사용되며, 사용 시 보안상 취약하기 때문에 서비스 포트가 열려 있을 경우, 침해사고에 노출될 수 있다. 따라서 Remote Log 서버를 사용하지 않는 경우, syslog 전송 Port 차단을 권고한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR30 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | Remote Log 서버를 사용하지 않을 경우 syslog 전송 Port를 차단한 경우 |
| 취약 조건 | Remote Log 서버를 사용하지 않고 UDP 514 Port를 사용 중인 경우 |

<!-- @block name=check_steps method_no=1 cols=step,text id=MT30 -->

XenServer 및 XenCenter Patch는 Xen 시스템을 Citrix에서 출시하고 난 뒤 Xen과 관련된 응용프로그램, 서비스, 실행 파일 등의 오류나 보안취약점 등을 수정하여 적용한 Update 파일이다. Update Patch 발표 후 취약성을 이용한 공격 도구가 먼저 출현할 수 있으므로, Update Patch는 발표 후 가능한 한 빨리 설치할 것을 권장한다.
