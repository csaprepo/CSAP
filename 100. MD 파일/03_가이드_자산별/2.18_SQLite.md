## GUIDE-SQT-001 DB 파일 권한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-SQT-001 |
| 플랫폼 | SQLite |
| 점검영역 | 보안 설정 |

### 항목 설명

비인가자가 DB 파일에 접근 가능하면 데이터 무단 변조, DB 파일 삭제, 외부 노출 등 각종 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | DB 파일의 접근 권한이 640 이하인 경우 |
| 취약 조건 | DB 파일의 접근 권한이 640 초과인 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • DB 파일 접근 권한 확인 |
| 2 | # ls –al [DB 파일명] |

### 조치 방법

|---:|---|

| 2 | # chmod 640 [DB 파일명] |

## GUIDE-SQT-002 중요 정보 암호화

### 점검 정보

### 항목 설명

DB 파일 또는 중요 데이터가 암호화되지 않은 상태로 외부 비인가자에게 유출될 경우 침해사고, 개인정보 유출 등 각종 위험이 존재한다.

|---|---|

| 취약 조건 | DB 파일 또는 중요 데이터를 암호화하고 있지 않은 경우 |

## GUIDE-SQT-003 안전한 암호화 알고리즘 사용

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-SQT-003 |
| 플랫폼 | SQLite |
| 점검영역 | 보안 설정 |

### 항목 설명

SHA-256 암호화 알고리즘은 단방향 알고리즘으로 평문을 암호화했을 때 다시 평문으로 복호화할 수 없는 암호화 알고리즘이다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | DB 파일 또는 중요 데이터 암호화 시 SHA-256 이상 암호화 알고리즘을 사용하고 있는 경우 |
| 취약 조건 | DB 파일 또는 중요 데이터 암호화 시 SHA-256 이상 암호화 알고리즘을 사용하고 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • SHA-256 이상의 암호화 알고리즘 사용 여부 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • SHA-256 이상 암호화 알고리즘 사용 |

### 비고

※ SQL Cipher 4.0.0 미만 버전에서는 SHA-1 알고리즘이 적용되므로 4.0.0 이상 버전 사용 권고

## GUIDE-SQT-004 실행 파일 권한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK4 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-SQT-004 |
| 플랫폼 | SQLite |
| 점검영역 | 보안 설정 |

### 항목 설명

실행 파일에 대한 접근 권한 및 소유자 설정이 취약하면 공격자가 실행 파일을 변경하거나 악성코드 삽입 등으로 인한 침해사고가 발생할 수 있고 이로 인해 중요 데이터의 유출, 데이터의 변조 등 각종 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 실행 파일의 소유자 및 소유그룹이 별도의 계정이고 권한이 750 이하인 경우 |
| 취약 조건 | 실행 파일의 소유자 및 소유그룹이 기본 계정이고 권한이 750 초과인 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 실행 파일 확인 |
| 2 | # which sqlite3 |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT4-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 실행 파일 소유자 및 소유그룹, 권한 확인 |
| 2 | # ls –al [파일명] |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

| 순서 | 절차 |
|---:|---|
| 1 | 1) 파일의 소유자 및 소유그룹을 별도의 계정으로 변경 |
| 2 | # chown dba:dba [파일명] |
| 3 | 2) Other의 실행 권한 제거 |
| 4 | # chmod 750 [파일명] |

| 취약 조건 | WAL mode 설정을 통해 로그를 저장하고 있지 않은 경우 |
