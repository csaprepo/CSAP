## GUIDE-NGX-001 웹 서비스 영역의 분리

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-NGX-001 |
| 플랫폼 | Nginx |
| 점검영역 | 보안 설정 |

### 항목 설명

Nginx 설치 시 html 디렉터리를 DocumentRoot로 사용하고 있는데 html 디렉터리는 공격에 이용될 수 있는 시스템 관련 정보도 포함하고 있으므로 이를 다른 경로로 변경하여 사용해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | default DocumentRoot를 사용하고 있는 경우 |
| 취약 조건 | default DocumentRoot를 사용하고 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • 기본 디렉터리 위치 확인 (예시) |
| 2 | 1) # cat [Nginx 환경 설정 파일] &#124; grep root |
| 3 | ※ default : /var/www/html |
| 4 | ※ 설치 OS 및 설치 방법에 따라 환경 설정 파일의 위치가 다름 |

<!-- @code id=CMD-001 block=check_steps language=sh -->

```sh
cat [Nginx 환경 설정 파일] | grep root
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • 기본 디렉터리 위치 변경 (예시) |
| 2 | 1) # vi [Nginx 환경 설정 파일] |

## GUIDE-NGX-002 불필요한 파일 제거

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-NGX-002 |
| 플랫폼 | Nginx |
| 점검영역 | 보안 설정 |

### 항목 설명

Nginx 설치 시 기본으로 생성되는 매뉴얼 파일 및 테스트 파일은 외부 침입자에게 시스템에 대한 정보를 제공할 수 있으므로 반드시 제거해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 매뉴얼 파일 및 디렉터리가 제거되어 있는 경우 |
| 취약 조건 | 매뉴얼 파일 및 디렉터리가 제거되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 불필요한 디렉터리 존재 여부 확인 |
| 2 | 1) 불필요한 파일 존재 여부 확인 (*.old, *.bak, 테스트 파일 등) |
| 3 | # ls –al [Nginx 설정 디렉터리] |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 불필요한 파일 삭제 |
| 2 | 1) 주기적으로 Nginx 설정 디렉터리 내 불필요한 파일(test, old, bak 파일 등)을 확인 |
| 3 | 2) # cd [Nginx 설치 디렉터리] |
| 4 | 3) # rm –rf [불필요한 파일명] |

### 비고

※ 파일 삭제 시, 시스템에 영향이 가는지 충분히 테스트를 진행하고 삭제 진행

## GUIDE-NGX-006 웹 프로세스 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK6 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-NGX-006 |
| 플랫폼 | Nginx |
| 점검영역 | 접근 관리 |

### 항목 설명

Web 서버 데몬이 root 계정 또는 root 권한으로 운영될 경우 Wen Application 취약점 또는 버퍼 오버플로우로 인하여 root 권한을 획득할 수 있다. 따라서 서버 데몬이 root 권한이 아닌 별도의 계정으로 운영되도록 해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR6 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 데몬이 root 또는 root 권한으로 구동되고 있지 않은 경우 |
| 취약 조건 | 데몬이 root 또는 root 권한으로 구동되고 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • Nginx 프로세스 소유자 권한 확인 |
| 2 | 1) # ps –ef &#124; grep nginx |

<!-- @code id=CMD-005 block=check_steps language=sh -->

```sh
ps -ef | grep nginx
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • Nginx 데몬 user/group 변경 |
| 2 | 1) user 지시자에 root가 아닌 별도의 계정으로 변경 |
| 3 | # vi [Nginx 설정 파일] |
| 4 | 2) 설정한 별도의 계정이 로그인할 수 없도록 nologin 설정 |
