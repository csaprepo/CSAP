## GUIDE-MNG-001 불필요한 데이터베이스 및 테이블 제거

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-MNG-001 |
| 플랫폼 | MongoDB |
| 점검영역 | 계정 관리 |

### 항목 설명

사용하지 않거나 테스트 용도의 데이터베이스(collection)가 존재하면 관리 미흡으로 인해 침해사고가 발생할 가능성이 있으므로 불필요한 데이터베이스 및 테이블을 제거해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 운영에 불필요한 데이터베이스, collection이 존재하지 않는 경우 |
| 취약 조건 | 운영에 불필요한 데이터베이스, collection이 존재하는 경우 |

## GUIDE-MNG-003 데몬 실행 시 인증 옵션 사용

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-MNG-003 |
| 플랫폼 | MongoDB |
| 점검영역 | 계정 관리 |

### 항목 설명

mongod(MongoDB 실행 데몬)를 실행할 때, 인증을 사용하는 옵션을 사용하여 비인가 사용자가 DB에 접근할 수 없도록 해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | mongod 환경설정 파일에 authorization이 enabled로 설정된 경우 |
| 취약 조건 | mongod 환경설정 파일에 authorization 값이 존재하지 않거나 true로 설정되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 인증 옵션 확인 |
| 2 | 1) # cat [MongoDB 환경설정 파일] &#124; grep auth (예시) |
| 3 | ※ default : authorization 값 존재하지 않음 |

<!-- @code id=CMD-001 block=check_steps language=sh -->

```sh
cat [MongoDB 환경설정 파일] | grep auth
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 인증 옵션 사용 활성화 |
| 2 | 1) 환경설정 파일 내 security 필드 아래 authorization 값 enabled 설정 |
| 3 | ※ MongoDB v3.0 이하에서는 auth=true로 설정 |

<!-- @block name=remediation method_no=2 cols=step,text id=RM3-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • MongoDB 재구동 (예시) |
| 2 | 1) # systemctl restart mongod |

<!-- @block name=remediation method_no=3 cols=step,text id=RM3-3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 사용자 인증 확인 |
| 2 | 1) > db.auth(“사용자 계정”, “패스워드”); |

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

|---:|---|
| 1 | • 계정 목록 확인 |
| 2 | 1) > use admin; |
| 3 | 2) > show users; |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 관리자 계정 생성 |
| 2 | 1) 쿼리 입력 |
| 3 | > db.createUser({user: “관리자 계정명”, pwd: “패스워드”, roles: [“readWriteAnyDatabase”,“userAdminAnyDatabase”,“dbAdminAnyDatabase”]}); |
| 4 | ※ roles : superuser 권한(root)은 사용하지 않도록 설정 |

### 비고

<!-- @block name=table cols=role,description id=TB4 -->

| 권한 | 설명 |
|---|---|
| readWriteAnyDatabase | 전체 DB 읽기 쓰기 가능 |
| userAdminAnyDatabase | 전체 DB에서 역할과 사용자 생성, 수정 가능 |
| dbAdminAnyDatabase | 전체 DB 스키마 작업 가능, 권한 부여 불가 |
| root | 모든 DB의 권한을 부여 |

## GUIDE-MNG-005 주요 실행 및 설정 파일 권한 관리

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-MNG-005 |
| 플랫폼 | MongoDB |
| 점검영역 | 디렉터리 및 파일권한 관리 |

### 항목 설명

실행 파일로 이루어진 파일은 전체 시스템에 손상을 줄 수 있으므로 별도의 계정이나 관리자가 소유해야 하며, other 권한에 읽기, 쓰기, 실행 권한을 제거하여 임의의 실행 및 정보 탈취 위험으로부터 보호해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 실행 파일 및 설정 파일의 소유자 및 그룹이 별도의 계정의 소유이며 파일의 권한이 750(-rwxr-x---) 이하로 설정된 경우 |
| 취약 조건 | 실행 파일 및 설정 파일의 소유자 및 그룹이 별도의 계정의 소유가 아니며 파일의 권한이 750(-rwxr-x---) 초과로 설정된 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 실행 파일 권한 확인 (예시) |
| 2 | 1) # ls –al [MongoDB 실행 파일] &#124; grep “mongo*” |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT5-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 설정 파일 권한 확인 (예시) |
| 2 | 1) # ls -al [MongoDB 설정 파일] |

<!-- @code id=CMD-002 block=check_steps language=sh -->

```sh
ls -al [MongoDB 실행 파일] | grep "mongo*"
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 실행 파일, 설정 파일 소유자 수정 및 Others 실행 권한 제거 |

| 3 | 2) # chmod 750 [file명] |

### 비고

## GUIDE-MNG-007 데이터베이스 접근 제한 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK7 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-MNG-007 |
| 플랫폼 | MongoDB |
| 점검영역 | 디렉터리 및 파일권한 관리 |

### 항목 설명

MongoDB의 접근 제한을 설정하지 않으면 비인가 사용자가 데이터베이스에 접근하여 데이터를 열람, 수정, 삭제가 가능하므로 특정한 IP만 접근 가능하도록 접근 제한 설정을 해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR7 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 인가된 IP만 접근할 수 있도록 제한 설정을 한 경우 |
| 취약 조건 | 인가된 IP만 접근할 수 있도록 제한 설정을 하지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT7 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 환경 설정 파일에서 확인 |
| 2 | 1) # cat [MongoDB 환경 설정 파일] &#124; grep bind |
| 3 | ※ default : 127.0.0.1 |

<!-- @code id=CMD-003 block=check_steps language=sh -->

```sh
cat [MongoDB 환경 설정 파일] | grep bind
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM7 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 환경 설정 파일에서 bindip 수정 |
| 2 | 1) # vi [MongoDB 환경 설정 파일] |
| 3 | bindIp : 인가된 IP |

### 비고

※ bindIp가 설정되어 있지 않을 경우, 해당 DB의 서버 IP 접근 제한 정책도 함께 확인 필요
