## GUIDE-RED-001 Redis 인증 패스워드 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-RED-001 |
| 플랫폼 | Redis |
| 점검영역 | 보안 설정 |

### 항목 설명

Redis 패스워드 설정이 되어 있지 않은 경우, 비인가자가 데이터베이스에 접근이 가능하며 이로 인해 데이터베이스 장악 및 정보 유출의 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 인증패스워드가 설정되어 있는 경우 |
| 취약 조건 | 인증패스워드가 설정되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • 인증 패스워드 설정 |
| 2 | 1) # cat [redis 디렉터리/redis.conf] &#124; grep –i requirepass |

<!-- @code id=CMD-001 block=check_steps language=sh -->

```sh
cat [redis 디렉터리/redis.conf] | grep -i requirepass
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • redis.conf 파일 안의 requirepass 설정 |
| 2 | 1) # vi /etc/redis/redis.conf |
| 3 | 2) requirepass 값 설정 |
| 4 | 3) 인증 로그인 확인 |

## GUIDE-RED-003 Slave 읽기 모드 전용 모드 설정

| 플랫폼 | Redis |
| 점검영역 | 보안 설정 |

### 항목 설명

Master와 Slave 환경에서 Slave에 read only 기능만을 설정하여 Master에 있는 자원을 변경할 수 없도록 해야 한다.

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |

| 취약 조건 | Slave에 쓰기 설정이 가능하도록 설정되어 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • redis.conf 파일 내 replica-read-only 설정 확인 |
| 2 | 1) cat [redis 디렉터리]/redis.conf &#124; grep –i replica-read-only |

```sh
cat [redis 디렉터리]/redis.conf | grep -i replica-read-only
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • redis.conf 파일 내 replica-read-only 설정 |

## GUIDE-RED-004 rename-command 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK4 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-RED-004 |
| 플랫폼 | Redis |
| 점검영역 | 보안 설정 |

### 항목 설명

공유되는 환경에서는 위험한 command들의 이름을 변경할 수 없다. 비인가된 사용자가 환경을 변경하거나 데이터를 가져오는 위험한 command를 사용할 수 없도록 설정해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | rename-command CONFIG를 빈칸으로 설정하고 있거나 운영상 필요한 command외 나머지 command의 이름을 변경하여 사용하고 있는 경우 |
| 취약 조건 | rename-command CONFIG 설정이 되어 있지 않은 경우(주석 처리 되어 있는 경우) |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • redis.conf 파일 안의 rename-command CONFIG 확인 |
| 2 | 1) cat [redis 디렉터리]/redis.conf &#124; grep –i rename-command |

<!-- @code id=CMD-004 block=check_steps language=sh -->

```sh
cat [redis 디렉터리]/redis.conf | grep -i rename-command
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • redis.conf 파일 안의 rename-command CONFIG 설정 |
| 2 | 1) # vi [redis 디렉터리]/redis.conf |
| 3 | rename-command CONFIG “” 주석 처리 해제 |

## GUIDE-RED-005 데이터 디렉터리 접근 권한 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-RED-005 |
| 플랫폼 | Redis |
| 점검영역 | 디렉터리 및 파일권한 관리 |

### 항목 설명

일반 사용자가 redis 설치 디렉토리에 임의의 파일을 생성, 삭제 및 변경할 수 있으면 중요 파일 삭제, 백도어 삽입 등의 피해가 발생할 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 데이터 디렉토리의 접근 권한이 750(-rwxr-x---) 이하인 경우 |
| 취약 조건 | 데이터 디렉토리의 접근 권한이 750(-rwxr-x---) 초과인 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • redis 데이터 디렉터리 접근 권한 확인 |
| 2 | 예시) |
| 3 | 1) ls –ld [redis 데이터 디렉터리] |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • redis 데이터 디렉터리 접근 권한 750으로 설정 |
| 2 | 1) # chmod 750 [redis 데이터 디렉터리] |

## GUIDE-RED-006 설정 파일 접근권한 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK6 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-RED-006 |
| 플랫폼 | Redis |
| 점검영역 | 디렉터리 및 파일권한 관리 |

### 항목 설명

설정 파일에 other 권한이 존재할 경우, 비인가자가 설정 파일에 접근하여 설정 변경을 통해 서비스 장애를 일으킬 위험이 존재하며 또한 설정 파일을 통해 정보를 획득하여 2차 공격의 정보로 사용할 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR6 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 설정 파일의 접근 권한이 600(-rw-------) 이하로 설정되어 있는 경우 |
| 취약 조건 | 설정 파일의 접근 권한이 600(-rw-------) 초과로 설정되어 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • redis 디렉터리의 redis.conf 권한 확인 |
| 2 | 예시) |
| 3 | 1) # ls –al [redis 디렉터리]/redis.conf |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • redis.conf 파일의 권한을 600 이하로 설정 |
| 2 | 1) # chmod 600 [redis 데이터디렉터리]/redis.conf |
