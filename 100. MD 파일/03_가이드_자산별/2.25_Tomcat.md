## GUIDE-TOM-001 default 관리자 계정명

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-TOM-001 |
| 플랫폼 | Tomcat |
| 점검영역 | 계정 관리 |

### 항목 설명

Tomcat의 디폴트 계정을 그대로 사용할 경우 비인가 사용자가 패스워드 추측 공격을 통해 Web Server에 접속할 수 있으므로 패스워드를 유추하기 어려운 계정명으로 변경해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 계정명이 default 계정명으로 설정되어 있지 않은 경우 |
| 취약 조건 | 계정명이 default 계정명으로 설정되어 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • 계정 사용 여부 확인 |
| 2 | 1) # cat [Tomcat 설치 디렉터리]/tomcat-users.xml &#124; grep “<user username=” |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 관리자 페이지 활성화 확인 |
| 2 | 1) # cat [Tomcat 설치 디렉터리]/tomcat-users.xml &#124; grep “roles=” |
| 3 | ※ roles = manager-gui, manager-script, manager-jmx, manager-status로 설정되어 있으면 관리자 계정 및 페이지 활성화 상태 |

<!-- @code id=CMD-001 block=check_steps language=sh -->

```sh
cat [Tomcat 설치 디렉터리]/tomcat-users.xml | grep "<user username="
```

## GUIDE-TOM-002 취약한 패스워드 사용 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-TOM-002 |
| 플랫폼 | Tomcat |
| 점검영역 | 계정 관리 |

### 항목 설명

관리자 계정의 패스워드를 취약하게 설정하여 사용하는 경우에 비인가 사용자가 패스워드 유추 공격을 통하여 관리자 권한을 획득할 수 있으므로 패스워드 복잡도를 만족하여 패스워드를 설정해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 관리자 패스워드가 암호화되어 있거나 패스워드 복잡도 설정을 만족하고 있는 경우 |
| 취약 조건 | 관리자 패스워드가 암호화되어 있지 않거나 패스워드 복잡도 설정을 만족하고 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 계정 패스워드 확인 |
| 2 | 1) # [Tomcat 설치 디렉터리]/tomcat-users.xml &#124; grep “<user username=” |
| 3 | 2) password 필드 확인 |
| 4 | ※ default 패스워드 : “must-be-changed” |

<!-- @code id=CMD-002 block=check_steps language=sh -->

```sh
[Tomcat 설치 디렉터리]/tomcat-users.xml | grep "<user username="
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 패스워드 변경 |
| 2 | 1) 패스워드 복잡도를 만족하도록 설정 |
| 3 | # vi [Tomcat 설치 디렉터리]/tomcat-users.xml |
| 4 | ※ 패스워드 복잡도 : 영문(대문자, 소문자), 숫자, 특수문자 조합 중 3가지 8자리 이상, 2가지 조합 10자리 이상 |

### 비고

※ 관리자 페이지를 사용하지 않는 경우 양호로 처리함

## GUIDE-TOM-003 패스워드 파일 권한 관리

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-TOM-003 |
| 플랫폼 | Tomcat |
| 점검영역 | 보안 설정 |

### 항목 설명

패스워드 설정 파일이 비인가 사용자에게 노출되면 패스워드를 이용하여 Web Server에 접속하는 침해사고가 발생할 가능성이 있으므로 패스워드 파일의 접근권한을 제한해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 패스워드 파일의 접근 권한이 600(-rw-------) 이하로 설정되어 있는 경우 |
| 취약 조건 | 패스워드 파일의 접근 권한이 600(-rw-------) 이하로 설정되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 패스워드 파일 권한 설정 확인 |
| 2 | 1) # ls [Tomcat 설치 디렉터리 ] -l |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 패스워드 파일 권한 변경 |
| 2 | 1) # chmod 600 [Tomcat 설치 디렉터리]/tomcat-users.xml |
| 3 | ※ 설정 파일 권한 변경 시, 시스템 영향도를 파악하여 충분한 테스트를 진행 한 후에 접근권한 수정 |

## GUIDE-TOM-004 홈 디렉터리 쓰기 권한 관리

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-TOM-004 |
| 플랫폼 | Tomcat |
| 점검영역 | 보안 설정 |

### 항목 설명

일반 사용자가 웹 서버 홈 디렉터리 또는 설정 관리 서버 디렉터리 및 매니지드 구동 서버 디렉터리에 임의의 파일을 생성, 삭제를 할 수 있으면 홈페이지 변조, 중요 파일 삭제, 백도어 삽입 등 피해가 발생할 수 있으므로 홈 디렉터리의 쓰기 권한을 제한 해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 홈 디렉터리 또는 웹 서버, 관리 서버 디렉터리 권한이 755(-rwx-r-x-r-x) 이하로 설정되어 있는 경우 |
| 취약 조건 | 홈 디렉터리 또는 웹 서버, 관리 서버 디렉터리 권한이 755(-rwx-r-x-r-x) 초과로 설정되어 있는 경우 |

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

|---:|---|

| 2 | 1) # cat [Tomcat 환경 설정 디렉터리]/server.xml &#124; grep appBase (예시) |
| 3 | 2) # ls –al [Tomcat 설치 디렉터리] |

<!-- @code id=CMD-003 block=check_steps language=sh -->

```sh
cat [Tomcat 환경 설정 디렉터리]/server.xml | grep appBase
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

## GUIDE-TOM-005 환경 설정 파일 권한 관리

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-TOM-005 |
| 플랫폼 | Tomcat |
| 점검영역 | 보안 설정 |

### 항목 설명

일반 사용자가 웹 사이트 소스 파일을 삭제, 변경할 수 있으면, 홈페이지 변조, 작업 실수로 인한 파일 삭제, 백도어 삽입 등의 피해가 발생할 수 있다. 이로 인해 시스템이 오작동하여 사용 불능 상태에 빠질 우려가 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | WAS 전용 계정 소유이고 소스파일 접근 권한 644, 설정 파일 접근 권한 600으로 설정되어 있는 경우 |
| 취약 조건 | WAS 전용 계정 소유이고 소스파일 접근 권한 644, 설정 파일 접근 권한 600으로 설정되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 설정 파일 및 소스 파일 접근 권한 확인 |
| 2 | 1) # ls –al [Tomcat 설치 디렉터리] |
| 3 | ※ 설정 파일 : *.xml, *.properties, *.policy 등 |
| 4 | 2) # cat [Tomcat 설치 디렉터리]/server.xml &#124; grep appBase (예시) |
| 5 | ※ 소스 파일 : server.xml 또는 (appBase 설정 파일) |

<!-- @code id=CMD-004 block=check_steps language=sh -->

```sh
cat [Tomcat 설치 디렉터리]/server.xml | grep appBase
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 파일 권한 변경 |
| 2 | 1) 설정 파일 권한 변경 |
| 3 | # chmod 600 [해당 파일] |
| 4 | 2) 소스 파일 권한 변경 |
| 5 | # chmod 644 [해당 파일] |

## GUIDE-TOM-008 로그 파일 관리 및 주기적 백업

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK8 -->

| 점검영역 | 패치 및 로그 관리 |

### 항목 설명

침해 사고 발생 시, 로그 파일은 사고 원인을 분석하는데 사용되는 중요한 자료로써 사용되며 유지보수 및 시스템 업데이트 시에 장애 및 외부 침입 등에 대한 변조가 발생하는 경우를 대비하여 백업 정책을 세워 로그 파일을 관리하고 주기적으로 백업해야 한다.

| 취약 조건 | 로그 파일을 관리하고 있으며 주기적으로 백업하고 있지 않은 경우 |
