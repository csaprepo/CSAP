## GUIDE-CPH-001 Keyring 파일 소유자 및 권한 확인

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-CPH-001 |
| 플랫폼 | Ceph |
| 점검영역 | 파일 및 디렉터리 권한 |

### 항목 설명

Keyring 파일은 인증 정보(패스워드, 권한)가 저장되어 있는 파일이다. 만약 해당 파일에 Other 권한이 존재할 경우 비인가자가 Keyring 파일을 수정하여 시스템 장애를 발생시키거나 인증 정보를 탈취하여 Ceph 시스템에 접속한 후 중요 정보를 열람, 수정, 삭제할 가능성이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | Keyring 파일 소유자가 root 또는 관리자 계정이고, 권한이 400(-r--------)으로 설정된 경우 |
| 취약 조건 | Keyring 파일 소유자가 root 또는 관리자 계정이고, 권한이 400(-r--------)으로 설정되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • Keyring 소유자 및 파일 권한 확인 |
| 2 | 1) # ls [keyring 파일 디렉터리]/keyring 파일 |
| 3 | 예시) |
| 4 | ls –l /etc/ceph/*.keyring |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • Keyring 소유자 및 파일 권한 변경 |
| 2 | 1) # chown root:root [keyring 파일 디렉터리]/keyring 파일 |
| 3 | 2) # chmod 400 [keyring 파일 디렉터리]/keyring 파일 |

## GUIDE-CPH-002 SSH 인증키 파일 관리

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-CPH-002 |
| 플랫폼 | Ceph |
| 점검영역 | 파일 및 디렉터리 권한 |

### 항목 설명

Ceph는 중앙 Management 서버에서 ssh를 이용해 노드들의 설정 변경과 배포를 할 수 있다. 이때 패스워드가 아닌 키를 생성하여 사용하게 되는데, 키는 파일에 기록되어 있다. 만약 비인가자가 키 파일을 수정할 경우 시스템에 장애가 발생할 가능성이 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | .ssh 디렉터리 권한이 700(-rwx------)이고 SSH 키 파일에 Other 쓰기 권한이 없는 경우 |
| 취약 조건 | .ssh 디렉터리 권한이 700(-rwx------)이 아니거나 SSH 키 파일에 Other 쓰기 권한이 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • SSH 디렉터리 권한 확인 |
| 2 | 1) # ls –ld ~/.ssh |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT2-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • SSH 키 파일 권한 확인 |
| 2 | 1) # ls –l ~/.ssh |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • .ssh 디렉터리 권한 변경 |
| 2 | 1) # chmod 700 ~/.ssh |

<!-- @block name=remediation method_no=2 cols=step,text id=RM2-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • ssh 키 파일 권한 변경 |
| 2 | 1) # chmod 600 ~/.ssh/키 파일 |

## GUIDE-CPH-005 root 이외의 관리자 계정 사용

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-CPH-005 |
| 플랫폼 | Ceph |
| 점검영역 | 보안 설정 |

### 항목 설명

Ceph 설정 및 배포는 root 권한이 필요하다. root 계정을 사용할 경우, ssh의 root 계정 접속 금지 설정 등을 적용할 수 없어 root 계정이 외부로 노출될 수 있다. 따라서 root 권한을 가진 별도의 계정을 생성하여 Ceph를 설정 및 배포해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 별도의 관리자 계정을 사용하는 경우 |
| 취약 조건 | root 계정을 통해 Ceph를 관리하는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 관리자 계정 생성 여부 확인 |
| 2 | 1) # cat /etc/sudoers |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 별도의 관리자 계정 생성 |
| 2 | 예시) |
| 3 | 1) 계정 생성 |
| 4 | # useradd admin |
| 5 | 2) 생성된 계정에 관리자 계정 부여 |
| 6 | # chmod 660 /etc/sudoers 명령어를 통해 sudoers 파일 쓰기 권한 부여 |
| 7 | # vi /etc/sudoers 명령어 입력 후 아래와 같이 작성 |
| 8 | # chmod 440 /etc/sudoers 명령어를 통해 sudoers 파일 쓰기 권한 제거 |

### 비고

※ ceph 계정은 ceph 구동에 사용되는 계정이므로 ceph 이름을 제외한 다른 이름의 관리자 계정을 생성해야 함

## GUIDE-CPH-006 Selinux 활성화

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK6 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-CPH-006 |
| 플랫폼 | Ceph |
| 점검영역 | 보안 설정 |

### 항목 설명

SELinux는 Linux의 보안 모듈로 신뢰할 수 없는 입력으로부터 프로세스를 보호하고, 데이터의 기밀성, 무결성을 강화할 때 사용된다. Ceph가 설치된 서버에 SELinux를 활성화하여 권한 상승 공격 등을 방어할 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR6 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | SELinux가 활성화된 경우 |
| 취약 조건 | SELinux가 비활성화된 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • SELinux 활성화 여부 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • SELinux 활성화 |
