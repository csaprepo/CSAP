## GUIDE-ELS-002 디폴트 계정 및 패스워드 변경

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-ELS-002 |
| 플랫폼 | Elasticsearch |
| 점검영역 | 보안 설정 |

### 항목 설명

Elasticsearch는 인증을 위해 플러그인 설치 시 디폴트 계정 및 패스워드가 존재하며, 각 정보는 인터넷 등을 통해 쉽게 구할 수 있다. 이를 통해 악의적인 사용자가 디폴트 계정, 패스워드를 이용하여 Elasticsearch에 접근 가능하므로, 데이터 변조, 정보 유출 등의 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 디폴트 계정 및 패스워드를 변경한 경우 |
| 취약 조건 | 디폴트 계정 및 패스워드를 변경하지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • CURL 명령어을 통해 확인 (X-Pack 사용 시) |
| 2 | 1) 명령어를 통해 확인 (예시) |
| 3 | # curl –u test:test123 –XGET ‘http://localhost:9200/_xpack_security/user’ |
| 4 | ※ elastic 계정의 enabled 값이 false : 계정 비활성화 상태 (양호) |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT2-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 설정 파일을 통해 확인(Search-Guard 사용 시) |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 디폴트 계정 삭제/비활성화 (X-Pack 사용 시) |
| 2 | 1) 디폴트 계정을 비활성화하기 전 새로운 계정 생성 |
| 3 | 2) 관리자 권한 부여 |
| 4 | 3) 디폴트 계정 비활성화 |

<!-- @block name=remediation method_no=2 cols=step,text id=RM2-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 디폴트 계정 삭제/비활성화 (Search-Guard 사용 시) |
| 2 | 1) 디폴트 계정을 비활성화하기 전 새로운 계정 생성 |
| 3 | 2) # [Elasticsearch 설치 디렉터리]/plugins/search-guard-*/sgconfig/sg_internal_users.yml 파일을 수정하여 기존 관리자 계정 영역 삭제 및 신규 계정 및 패스워드 적용 |
| 4 | 3) # [Elasticsearch 설치 디렉터리]/plugins/search-guard-*/sgconfig/sg_roles_mapping.yml 파일을 수정하여 기존 관리자 계정 삭제 및 신규 계정 적용 |

### 비고

※ Elasticsearch Shield 플러그인의 경우 디폴트 계정이 존재하지 않음 ※ Elasticsearch X-Pack 플러그인의 경우 디폴트 계정은 elastic, 패스워드는 changeme로 설정되어 있음 ※ Elasticsearch Search-Guard 플러그인의 경우 디폴트 계정은 admin, 패스워드는 admin으로 설정되어 있음

| 점검영역 | 디렉터리 및 파일권한 관리 |

### 항목 설명

Elasticsearch 플러그인을 설치하게 되면 플러그인 디렉터리가 생성되고 그 안에서 설치한 플러그인을 관리하게 된다. 만약 일반 사용자가 해당 디렉터리에 접근이 가능할 경우 임의의 파일을 생성, 삭제 및 변경할 수 있으며 플러그인 파일 삭제, 백도어 삽입 등의 피해가 발생할 수 있다.

|---|---|
| 양호 조건 | 플러그인 디렉터리 권한이 750(-rwx-r-x----) 이하인 경우 |
| 취약 조건 | 플러그인 디렉터리 권한이 750(-rwx-r-x----) 초과된 경우 |
