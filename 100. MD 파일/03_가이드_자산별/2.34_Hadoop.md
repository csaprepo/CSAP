## GUIDE-HDP-001 로컬 파일 시스템/HDFS 디렉토리 소유자 및 권한 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 플랫폼 | Hadoop |
| 점검영역 | 파일 및 디렉터리 권한 |

### 항목 설명

파일에 과도한 사용자 권한이 존재할 경우, 비인가 된 사용자가 해당 파일에 접근하여 HDFS 등 하둡 관련 정보를 수집하여 2차적인 공격에 사용될 위험이 존재한다.

|---|---|

| 취약 조건 | 로컬 파일 시스템/HDFS 소유자가 권한이 조치 방법보다 과도하게 설정되어 있는 경우 |

## GUIDE-HDP-002 커버로스 인증 시 클러스터의 모든 시스템에서 YARN User 키 테이블/맵리듀스 User 키 테이블 파일 권한 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-HDP-002 |
| 플랫폼 | Hadoop |
| 점검영역 | 파일 및 서비스 |

### 항목 설명

하둡 서비스는 티켓을 얻기 위해 암호화된 로그인 사용이 불가능하다. 그러므로 사용자의 인증 자격 증명을 위하여 각 서비스 및 하위 서비스에 Kerberos와 관련 있는 사용자 키 테이블 파일을 통해 인증된 사용자만 접근이 가능하도록 설정하여야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 클러스터의 모든 시스템에 YARN User 키 테이블/맵리듀스 유저 키테이블의 권한이 400(-r--------) 이하이고 소유자가 해당 keytab의 소유자일 경우 |
| 취약 조건 | 클러스터의 모든 시스템에 YARN User 키 테이블/맵리듀스 유저 키테이블의 권한이 400(-r--------) 초과이고 소유자가 root일 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 수동점검을 통해 직접 hadoop 안에 커버로스 관련 키 테이블이 존재하는지 확인 |
| 2 | 1) # ls –al [hadoop config 디렉토리] &#124; grep *.keytab |

<!-- @code id=CMD-001 block=check_steps language=sh -->

```sh
ls -al [hadoop config 디렉토리] | grep *.keytab
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • root 외의 소유자로 지정, 권한은 400 이하로 설정 (예시) |
| 2 | # chown hdfs:hadoop hdfs.keytab |
| 3 | # chmod 400 hdfs.keytab |
| 4 | # chown yarn:hadoop yarn.keytab |
| 5 | # chmod 400 yarn.keytab |
| 6 | # chown mapred:hadoop mapred.keytab |
| 7 | # chmod 400 mapred.keytab |

## GUIDE-HDP-006 RPC 암호화

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK6 -->

| 항목 | 내용 |

| 플랫폼 | Hadoop |
| 점검영역 | 보안 설정 |

### 항목 설명

하둡 클라이언트는 하둡 네임노드와 통신하기 위해 하둡 RPC를 이용한다. 하둡 RPC 메커니즘은 SASL 보안을 지원한다. SASL 암호화는 하둡 클라이언트와 네임노드 간의 통신을 보호하고 암호화한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR6 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | rpc 암호화 설정을 적용한 경우 |
| 취약 조건 | rpc 암호화 설정을 적용하지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • core-site.xml 파일을 통해 암호화 설정 여부 확인 |
| 2 | 1) core-site.xml 확인 |
| 3 | # cat core-site.xml |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • core-site.xml 파일 rpc 암호화 설정 |
| 2 | 1) 아래와 같은 설정 사항 추가 |

<!-- @block name=figure id=FG2 -->

```text
<property>
        <name>hadoop.rpc.protection</name>
        <value>privacy</value>
</property>
```

### 비고

※ dfs.encrypt.data.transfer 속성 변경은 데이터 노드에서만 필요함
