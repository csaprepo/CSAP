## GUIDE-BUA-001 계정 잠금 임계값 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-BUA-001 |
| 플랫폼 | BOSH(UAA) |
| 점검영역 | 보안 설정 |

### 항목 설명

침입자로부터 패스워드 무작위 대입 공격이나 패스워드 추측 공격에 대하여 암호입력 실패 시도 횟수를 제한함으로써 전수 및 사전 공격을 차단하고 공격 시도 가용시간을 지연시킬 수 있다. 따라서 계정 잠금 임계값을 적절하게 설정해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 계정 잠금 임계값 설정이 5회 이하로 설정된 경우 |
| 취약 조건 | 계정 잠금 임계값 설정이 5회 초과로 설정된 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • 계정 잠금 임계값 설정 확인 |
| 2 | 1) uaa.yml 파일을 확인하여 파일 내 authentication.policy.global.lockoutAfterFailures 설정 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • 계정 잠금 임계값 설정 |
| 2 | 1) uaa.authentication.policy.global.lockoutAfterFailures 속성에 5 설정 lockoutAfterFailures: 5 |

## GUIDE-BUA-002 패스워드 복잡도 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-BUA-002 |
| 플랫폼 | BOSH(UAA) |
| 점검영역 | 보안 설정 |

### 항목 설명

추측 가능한 패스워드 및 default 패스워드를 사용할 경우, 공격자가 패스워드를 탈취 후 시스템에 접속하여 악의적인 영향을 줄 수 있으므로 패스워드 복잡도 설정을 만족하여 패스워드를 설정해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 패스워드 복잡도 설정(영문자, 숫자, 특수문자 중 3가지 조합 8자리 이상 또는 2가지 조합 10자리 이상)이 적용된 경우 |
| 취약 조건 | 패스워드 복잡도 설정이 적용되지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 패스워드 복잡도 설정 확인 |
| 2 | 1) 대시보드 또는 uaa.yml 파일을 확인하여 client.secret.policy.global 설정 확인 |
| 3 | ※ 참고) |
| 4 | maxLength: 최대 문자 수 (default: 255) |
| 5 | minLength: 최소 문자 수 (default: 0) |
| 6 | requireDigit: 최소 숫자 수 (default: 0) |
| 7 | requireLowerCaseCharacter: 최소 소문자 수 (default: 0) |
| 8 | requireSpecialCharacter: 최소 특수문자 수 (default: 0) requireUpperCaseCharacter: 최소 대문자 수 (default: 0) |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 패스워드 복잡도 설정 설정 |
| 2 | 1) uaa.yml 파일 내 패스워드 복잡도 설정(client.secret.policy.global) |

## GUIDE-BUA-003 세션 타임아웃 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-BUA-003 |
| 플랫폼 | BOSH(UAA) |
| 점검영역 | 보안 설정 |

### 항목 설명

일정 시간 동안 통신이 없는 경우, 해당 세션을 종료시킬 수 있도록 적절한 타임아웃을 설정해야 한다. 이로 인해 불필요한 세션을 정리하고 보안을 강화할 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 세션 타임아웃 설정이 10분 이하로 설정된 경우 |
| 취약 조건 | 세션 타임아웃 설정이 10분 초과로 설정된 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 세션 타임아웃 설정값 확인 |
| 2 | 1) uaa.yml 파일을 확인하여 uaa.servlet.idle-timeout 설정 확인 |
| 3 | idle-timeout: 1800 |
| 4 | ※ default 설정 : 1800(30분) |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 세션 타임아웃 설정 |
| 2 | 1) uaa.yml 파일의 uaa.servlet.idle-timeout 속성값을 600초(10분)로 설정 |

HTTP 통신 시 통신채널을 보호하고 안전한 통신을 사용할 수 있도록 http 프로토콜을 사용하지 않고 https 프로토콜을 사용해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | https 프로토콜을 사용하는 경우 |
| 취약 조건 | https 프로토콜을 사용하지 않는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • https 설정 여부 확인 |
| 2 | 1) uaa.yml 파일을 확인하여 login.protocol 설정 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • https 설정 |
| 2 | 1) uaa.파일을 login.protocol 속성에 https 설정 |
| 3 | login.protocol: https |

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

## GUIDE-BUA-006 최신 보안 패치 적용

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK6 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-BUA-006 |
| 플랫폼 | BOSH(UAA) |
| 점검영역 | 로그 관리 및 보안 패치 |

### 항목 설명

신 보안 패치를 수행하지 않을 경우 버전 취약점이 존재할 수 있으며 해당 취약점을 통해 시스템이 장악될 위험이 존재한다. 따라서 사용하고 있는 버전에 취약점 존재 여부를 주기적으로 확인하고 최신 보안패치를 수행해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR6 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 최신 보안 패치를 적용한 경우 |
| 취약 조건 | 최신 보안 패치를 적용하지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • UAA 버전 확인 (예시) |
| 2 | 1) 설치 디렉터리 내 uaa.yml 파일 내용 확인 |
| 3 | 참고) bosh-lite 사용 |
| 4 | 설치 디렉터리: /root/workspace |
| 5 | bosh-lite 다운로드 파일: paasta-5.0 |
| 6 | uaa.yml 경로: root/workspace/paasta-5.0/deployment/bosh-deployment/uaa.yml |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 최신 보안 패치 적용 시 시스템 영향도를 파악하여 충분한 테스트 후 적용 권고 |
| 2 | ※ 최신 버전을 사용하도록 권고하고 있으나 시스템 운영상 적용이 어려운 경우 최신이 아닌 취약점이 존재하지 않는 버전도 허용하고 있음 |
