## GUIDE-ORA-001 디폴트 계정 및 패스워드 변경

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-ORA-001 |
| 플랫폼 | Oracle |
| 점검영역 | 계정 관리 |

### 항목 설명

DBMS 기본 계정 디폴트 패스워드 및 권한 정책을 변경하지 않을 경우 비인가자가 DBMS 기본 계정과 디폴트 패스워드를 통해 DB에 접근할 수 있으며, 기본 계정에 부여된 권한을 악용하여 DB 정보를 유출할 수 있는 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 기본 계정의 디폴트 패스워드 및 권한 정책을 변경하여 사용하는 경우 |
| 취약 조건 | 기본 계정의 디폴트 패스워드 및 권한 정책을 변경하지 않고 사용하는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • 기본 계정 및 패스워드 정보 확인 |
| 2 | (User / Password) |
| 3 | scott / tiger or tigger, system / manager, |
| 4 | dbsnmp / dbsnmp, sys / chageon_install, |
| 5 | tracesvr / trace, outln / outln, |
| 6 | ordplugins / ordplugins, ordsys / ordsys, |
| 7 | ctxsys / ctxsys, mdsys / mdsys, |
| 8 | adams / wood, blake / papr, |
| 9 | clark / clth, jones / steel, |
| 10 | lbacsys / lbacsys |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • 사용되는 계정의 경우 패스워드 변경 후 사용 |
| 2 | SQL> alter user username identified by new_password; |
| 3 | ※ 그 이외에 객체 권한 부여, 기본 role 확인 및 변경 수행 |
| 4 | ※ DBSNMP 파일의 접근권한 설정이 필요함 |
| 5 | # chmod 700 snmp_rw.ora |

<!-- @block name=remediation method_no=2 cols=step,text id=RM-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 불필요한 계정 삭제 |
| 2 | SQL> DROP USER ‘username’; |

## GUIDE-ORA-002 불필요한 계정 제거

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-ORA-002 |
| 플랫폼 | Oracle |
| 점검영역 | 계정 관리 |

### 항목 설명

DB 관리나 운용에 사용하지 않는 불필요한 계정이 존재할 경우 비인가자가 불필요한 계정을 이용하여 DB의 데이터를 열람, 삭제, 수정할 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 계정 정보를 확인하여 불필요한 계정이 없는 경우 |
| 취약 조건 | 인가되지 않은 계정, 퇴직자 계정, 테스트 계정 등 불필요한 계정이 존재하는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 활성화 계정 확인 |
| 2 | SQL> SELECT USERNAME, ACCOUNT_STATUS FROM DBA_USERS WHERE ACCOUNT_STATUS=’OPEN’; |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 활성화 계정 중 불필요한 계정 삭제 |
| 2 | SQL> DROP USER ‘username’; |

### 비고

￭ 활성화 계정 중 일부 시스템 계정 제외 - SYS, SYSTEM, SYSMAN, DBSNMP, MGMT_VIEW

## GUIDE-ORA-003 기관 보안 정책과 패스워드 정책 일치

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |

| 플랫폼 | Oracle |
| 점검영역 | 계정 관리 |

### 항목 설명

패스워드 사용기간 및 복잡도 설정 유무를 점검하여 비인가자의 패스워드 추측 공격(무작위 대입 공격, 사전 대입 공격 등)에 대한 대비가 되어있는지 확인한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|

| 취약 조건 | 기관 정책에 맞게 패스워드 사용기간 및 복잡도 설정이 적용되어 있지 않는 경우 |

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

<!-- @block name=check_steps method_no=2 cols=step,text id=MT3-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 프로파일 리소스 확인 |
| 2 | SQL> SELECT PROFILE, RESOURCE_NAME, LIMIT FROM DBA_PROFILES; |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 프로파일 리소스 수정 |
| 2 | SQL> ALTER PROFILE ‘profile_name’ LIMIT ‘resource_name’ value |
| 3 | 예시) |
| 4 | SQL> ALTER PROFILE CLOUD1 LIMIT ‘PASSWORD_LIFE_TIME’ 90; (패스워드 최대 사용일을 90일로 설정) |
| 5 | SQL> ALTER PROFILE CLOUD1 LIMIT ‘PASSWORD_VERIFY_FUNCTION’ VERIFY_FUNCTION; (패스워드 점검 함수로 VERIFY_FUNCTION 사용) |

### 비고

￭ 활성화된 유저가 적용된 모든 프로파일에 설정해야 함 - PASSWORD_LIFE_TIME : 비밀번호 유효 기간 - PASSWORD_REUSE_TIME : 비밀번호를 재사용할 수 없는 일 수 - PASSWORD_REUSE_MAX : 현재 암호를 재사용하기 전 필요한 암호 변경 횟수 - PASSWORD_VERIFY_FUNCTION : 비밀번호 복잡성 검사 함수 설정 - PASSWORD_LOCK_TIME : 지정된 로그인 실패 횟수 이후 계정이 잠기는 일 수 - PASSWORD_GRACE_TIME : 암호 만기 후 변경까지의 유예 기간

## GUIDE-ORA-004 관리자 권한 설정

관리자 권한을 최소한의 계정과 그룹에만 부여하였는지를 점검하여, 관리자 권한의 오남용을 방지하고 관리자 계정 유출로 인한 비인가자의 DB접근 가능성을 최소화해야 한다.

| 취약 조건 | 관리자 권한이 필요 없는 계정 및 그룹에 권한이 부여된 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 3 | ※ 계정 출력 시 취약 |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT4-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • Admin에 부적합 계정 존재 여부 점검 |
| 2 | SQL> SELECT GRANTEE, PRIVILEGE FROM DBA_SYS_PRIVS WHERE GRANTEE NOT IN (‘SYS, ’SYSTEM’, ‘AQ_ADMINISTARTOR_ROLE’, ‘DBA’, ‘MDSYS’, ‘LBACSYS’, ‘SCHEDULER_ADMIN’, ‘WMSHS’) AND ADMIN_OPTION=’YES’ AND GRANTEE NOT IN (SELECT GRANTEE FROM DBA_ROLE_PRIVS WHERE GRANTED_ROLE=’DBA’); |
| 3 | ※ 계정 출력 시 취약 |

## GUIDE-ORA-005 원격에서 DB 서버로의 접속 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-ORA-005 |
| 플랫폼 | Oracle |
| 점검영역 | 접근 관리 |

### 항목 설명

허용되지 않은 IP 및 포트에 대한 접근 통제가 이루어지지 않을 경우, 원격에서의 DB 접근이 가능해져 공격자에 의해 네트워크 서비스 스캐닝을 통한 DB 사용 여부가 확인되어 DB 내의 데이터 유출 및 공격 대상이 될 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | DB 원격 접속을 제한하고 있는 경우 |
| 취약 조건 | DB 원격 접속을 제한하고 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 방화벽 등 보안 솔루션을 통해 원격에서 Oracle에 원격으로 접속이 가능한지 여부 파악 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 원격 OS 인증 방식이 불필요한 경우 REMOTE_OS_AUTHENT=FALSE로 설정 |
| 2 | 1) spfile을 사용하는 경우 |
| 3 | SQL> ALTER SYSTEM SET REMOTE_OS_AUTHENT=FALSE SCOPE=spfile; |
| 4 | 2) pfile을 사용하는 경우 `ini<SID>.ora` 파일 내에 설정 |
| 5 | SQL> ALTER SYSTEM SET REMOTE_OS_AUTHENT=FALSE; |

<!-- @block name=remediation method_no=2 cols=step,text id=RM5-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 방화벽 OS 인증이 필요한 경우 |
| 2 | 1) 방화벽을 통한 원격 접근 IP주소 제한 |
| 3 | 2) NAT를 사용하여 비공인 IP 주소 부여 후 외부 접근 제한 |

## GUIDE-ORA-006 사용자의 시스템 테이블 접근 권한 제거

<!-- @block name=control keys=control_id,asset,category id=CK6 -->

| 플랫폼 | Oracle |
| 점검영역 | 접근 관리 |

DBA만 접근 가능한 테이블에 일반 사용자 접근을 허용할 경우 비인가 사용자가 시스템의 주요 정보를 획득하거나, 주요 데이터베이스 설정 변경이 가능하다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR6 -->

| 판정 | 조건 |
|---|---|

| 취약 조건 | DBA만 접근 가능한 테이블에 일반 사용자 접근이 가능한 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT6 -->

| 순서 | 절차 |

| 2 | SQL> select grantee, privilege, owner, table_name from dba_tab_privs where (owner='SYS' or table_name like 'DBA_%') and privilege <> 'EXECUTE' and grantee not in ('PUBLIC', 'AQ_ADMINISTRATOR_ROLE', 'AQ_USER_ROLE', 'AURORA$JIS$UTILITY$', 'OSE$HTTP$ADMIN', 'TRACESVR', 'CTXSYS', 'DBA', 'DELETE_CATALOG_ROLE', 'EXECUTE_CATALOG_ROLE', 'EXP_FULL_DATABASE', 'GATHER_SYSTEM_STATISTICS', 'HS_ADMIN_ROLE', 'IMP_FULL_DATABASE', 'LOGSTDBY_ADMINISTRATOR', 'MDSYS', 'ODM', 'OEM_MONITOR', 'OLAPSYS', 'ORDSYS', 'OUTLN', 'RECOVERY_CATALOG_OWNER', 'SELECT_CATALOG_ROLE', 'SNMPAGENT', 'SYSTEM', 'WKSYS', 'WKUSER', 'WMSYS', 'WM_ADMIN_ROLE', 'XDB', 'LBACSYS', 'PERFSTAT', 'XDBADMIN', 'ADM_PARALLEL_EXECUTE_TASK', 'DBFS_ROLE', 'HS_ADMIN_SELECT_ROLE', 'OLAPI_TRACE_USER', 'OLAP_XS_ADMIN', 'OWB$CLIENT', 'SYSMAN') and grantee not in (select grantee from dba_role_privs where granted_role='DBA') and grantee not in (select username from dba_users where account_status !='OPEN') order by grantee; |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM6 -->

| 순서 | 절차 |
|---:|---|

| 2 | SQL> REVOKE 권한 ON 객체 FROM USER |

| 취약 조건 | OS_ROLES, REMOTE_OS_ROLES 설정이 TRUE로 설정되어 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT10 -->

| 순서 | 절차 |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT10-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • REMOTE_OS_ROLES 확인 |
| 2 | SQL> SHOW PARAMETER REMOTE_OS_ROLES; |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM10 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 설정 변경 |
