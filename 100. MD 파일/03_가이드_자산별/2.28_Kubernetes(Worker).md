## GUIDE-KWS-001 Kubelet 인증 제어

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-KWS-001 |
| 플랫폼 | Kubernetes(Worker) |
| 점검영역 | Kubelet Configuration |

### 항목 설명

Kubelet은 각 노드에서 실행되는 에이전트로 Pod에 대해 정의된 PodSpec(yaml 또는 Json 형태)에 따라 컨테이너를 실행하고 동작하도록 관리하는 역할을 한다. 따라서 Kubelet의 비인증 접근은 Pod와 컨테이너의 정보 노출, 리소스 수정 등에 대해 영향을 줄 수 있으므로 Kubelet 인증 후 접근할 수 있도록 해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 비인증 접근이 차단된 경우 |
| 취약 조건 | 비인증 접근이 허용된 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • Kubelet service 파일을 사용하는 경우 |
| 2 | 1) service 파일에 —anoymous-auth 설정이 false로 되어 있고 —read-only-port 설정이 0(비활성화)으로 되어 있는지 확인 |
| 3 | $ cat [kubelet service 파일 경로] &#124; grep “anonymous-auth\&#124;read-only-port” &#124; grep –v “#” |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • Kubelet config 파일을 사용하는 경우 |
| 2 | 1) config 파일에 —anonymous-auth 설정이 false로 되어 있고, --read-only-port 설정이 0(비활성화)으로 되어 있는지 확인 |
| 3 | $ cat [kubelet config 파일 경로] |

<!-- @code id=CMD-001 block=check_steps language=sh -->

```sh
cat [kubelet service 파일 경로] | grep "anonymous-auth\|read-only-port" | grep -v "#"
```

## GUIDE-KWS-003 Kubelet SSL/TLS 적용

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-KWS-003 |
| 플랫폼 | Kubernetes(Worker) |
| 점검영역 | Kubelet Configuration |

### 항목 설명

API server, node 간 통신 시 민감한 데이터들이 평문으로 전송되면 스니핑과 같은 방법으로 민감한 데이터가 노출되므로 SSL/TLS 통신을 적용하여 송수신되는 데이터들을 보호하고 접근하는 대상에 대해 인증해야 한다. SSL/TLS 통신 적용 시 주기적으로 인증서를 변경하고 안전한 cipher suite를 사용해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | kubelet SSL/TLS 통신을 위한 설정(인증서, 비밀키, 인증서 교환 주기, TLS 버전, cipher suites, hostname 변경 설정 비활성화)이 적용된 경우 |
| 취약 조건 | kubelet SSL/TLS 통신을 위한 설정(인증서, 비밀키, 인증서 교환 주기, TLS 버전, cipher suites, hostname 변경 설정 비활성화)이 적용되지 않은 경우 |

## GUIDE-KWS-004 Kernel 파라미터 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK4 -->

|---|---|

| 플랫폼 | Kubernetes(Worker) |

### 항목 설명

OS kernel 매개 변수값과 kubelet에 설정된 기본 kernel 매개 변수값이 다를 경우 kubelet 기본 kernel 매개 변수값이 변경되어 원하지 않는 커널 기능이 존재하는 Pod가 실행될 수 있으므로 각각의 변수값이 다를 경우 kubelet 기본 kernel 매개 변수값이 변경되지 않도록 보호해야 한다.

### 진단 기준

|---|---|
| 양호 조건 | Kubelet Default Kernel 값을 보호하는 경우 |
| 취약 조건 | Kubelet Default Kernel 값을 보호하지 않는 경우 |

## GUIDE-KWS-005 환경설정 파일 권한 설정

### 점검 정보

| 플랫폼 | Kubernetes(Worker) |
| 점검영역 | 파일 권한 설정 |

### 항목 설명

Kubernetes 설정 파일에 비인가자의 접근이 가능한 경우 Kubernetes 설정을 변경하여 침해 사고를 일으킬 가능성이 있다. 따라서 root 외 다른 사용자가 이 파일을 수정할 수 없도록 파일의 권한을 제한해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 환경설정 파일의 소유자 및 소유 그룹이 root이고, 접근 권한이 644 이하로 설정된 경우 |
| 취약 조건 | 환경설정 파일의 소유자 및 소유 그룹이 root가 아니거나, 접근 권한이 644 초과로 설정된 경우 |

### 진단 방법

| 순서 | 절차 |

| 1 | • Kubernetes 설정 파일 권한이 안전하게 설정되어 있는지 확인 |
| 2 | 1) kubelet.conf 설정파일 권한 확인 |
| 3 | $ stat –c %a:%U:%G /etc/kubernetes/kubelet.conf |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT5-2 -->

| 순서 | 절차 |
|---:|---|
