## GUIDE-RMQ-001 Guest 계정 제거

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-RMQ-001 |
| 플랫폼 | RabbitMQ |
| 점검영역 | 보안설정 |

### 항목 설명

RabbitMQ 최초 설치 시 관리자 권한을 가진 guest 계정이 존재한다. guest 계정이 존재할 경우 비인가자에 의해 설정이 변경되어 서비스에 영향을 줄 수 있다. 이러한 문제를 해결하기 위해 guest 계정을 제거하여 비인가자에 의한 피해를 최소화 할 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | guest 계정이 존재하지 않는 경우 |
| 취약 조건 | guest 계정이 존재하는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • guest 계정 조회 |
| 2 | 1) # [RabbitMQ 설치 디렉터리]/sbin/rabbitmqctl list_users |
| 3 | 예시) |
| 4 | rabbitmqctl list_users |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

|---:|---|
| 1 | • guest 계정 삭제 |
| 2 | 1) # [RabbitMQ 설치 디렉터리]/sbin/rabbitmqctl delete_user guest |

## GUIDE-RMQ-004 SSL 활성화

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK4 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-RMQ-004 |
| 플랫폼 | RabbitMQ |
| 점검영역 | 보안설정 |

### 항목 설명

RabbitMQ는 기본적으로 SSL이 비활성화되어 있다. 만약 SSL을 사용하지 않는다면 스니핑을 통해 RabbitMQ와 Producer 간의 메시지를 훔쳐볼 수 있다. 이를 방지하기 위해 SSL을 활성화하여 메시지를 암호화하면 데이터 도청을 방지할 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | SSL 설정이 활성화되어 있는 경우 |
| 취약 조건 | SSL 설정이 비활성화되어 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • SSL 활성화 여부 확인 |
| 2 | 1) # cat [RabbitMQ 설치 디렉터리]/rabbitmq.config |
| 3 | 예시) |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • SSL 활성화 |
| 2 | 1) # vi [RabbitMQ 설치 디렉터리]/rabbitmq.config |

### 비고

※ SSL 활성화 시, SSL 포트 2개가 활성화되므로 Producer에서 SSL 포트를 사용해야 함

## GUIDE-RMQ-005 Mnesia 데이터베이스 디렉터리 및 파일 권한 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-RMQ-005 |
| 플랫폼 | RabbitMQ |
| 점검영역 | 디렉터리 및 파일 권한 관리 |

### 항목 설명

RabbitMQ는 Erlang 언어로 제작되어 있으며 Mnesia 데이터베이스를 사용한다. Mnesia 데이터베이스에는 RabbitMQ 계정, 패스워드, 권한 등을 저장하며 파일 형태로 관리가 이루어진다. 만약 비인가자에 의해 데이터베이스 파일이 변조 또는 삭제될 경우 계정정보가 매칭되지 않으므로 서비스에 악영향을 끼칠 수 있다. 이를 방지하기 위해 Mnesia 데이터베이스 디렉터리 및 파일 권한에 other 권한을 제거해 비인가자에 의한 데이터베이스 파일의 변조 및 삭제를 막을 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | Mnesia 데이터 디렉터리 및 파일 권한에 Other 쓰기 권한이 존재하지 않을 경우 |
| 취약 조건 | Mnesia 데이터 디렉터리 및 파일 권한에 Other 쓰기 권한이 존재할 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • Mnesia 데이터 디렉터리 및 파일 권한 조회 |
| 2 | 1) # ls –l /[Mnesia 데이터 디렉터리] 권한 조회 |
| 3 | 2) # ls –l /[Mnesia 데이터 디렉터리]/ 데이터 파일 권한 조회 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 패스워드 관련 파일 권한 변경 |
| 2 | 1) # chmod o-w /Mnesia 데이터 디렉터리 명령어를 통해 Other 쓰기 권한 제거 |
| 3 | 2) # cd /Mnesia 데이터 디렉터리 이동 후 해당 디렉터리의 파일에 Other 쓰기 권한 제거 |

| 취약 조건 | 설정 파일의 Other에 쓰기 권한이 존재하는 경우 |
