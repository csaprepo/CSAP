## GUIDE-MSS-001 불필요한 계정 제거

### 항목 설명

데이터베이스의 계정 중 인가되지 않은 계정, 퇴직자 계정, 테스트 계정 등 업무에 사용하지 않는 불필요한 계정이 있는 경우 비인가자가 쉽게 데이터베이스에 접속하여 데이터를 열람, 삭제, 수정 등을 할 위험이 있다. 또한 DB 접속 시 지정된 IP주소만 접근 가능하도록 설정되어 있는지 확인하여 비인가자의 DB 접근을 제한해야 한다.

| 취약 조건 | 불필요한 계정이 존재하는 경우 |

## GUIDE-MSS-002 SYSADMIN 권한 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-MSS-002 |
| 플랫폼 | MS-SQL |
| 점검영역 | 계정 관리 |

### 항목 설명

sysadmin(시스템 관리자)의 역할은 SQL 서버와 설치된 데이터베이스에 대해서 완전한 관리 권한이 필요한 사용자를 위해 만들어진 역할로 이 역할의 구성원은 SQL 서버에서 모든 작업을 수행할 수 있으며 비인가 사용자 계정에 해당 권한이 부여될 경우, DB에 직접적인 공격이 가능해진다. 따라서 sysadmin 권한 제한 여부를 확인해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | sysadmin 역할 구성원에 관리자 구성원만 존재하는 경우 |
| 취약 조건 | sysadmin 역할 구성원에 불필요한 계정이 존재하는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 새 쿼리를 통해 확인 |
| 2 | 1) SQL Server Management Studio → 새 쿼리 |
| 3 | 2) EXEC sp_helpsrvrolemember ‘sysadmin’ |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT2-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 개체 탐색기를 통해 확인 |
| 2 | 1) SQL Server Management Studio → 개체 탐색기 → 보안 → 로그인 |
| 3 | 2) 계정별 오른쪽 마우스 → 속성 → 서버 역할에서 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 새 쿼리를 통해 역할 제거 |
| 2 | 1) SQL Server Management Studio → 새 쿼리 |
| 3 | 2) EXEC sp_droprolemember ‘<구성원 이름>’, ‘sysadmin’ |

<!-- @block name=remediation method_no=2 cols=step,text id=RM2-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 개체 탐색기를 통해 역할 제거 |
| 2 | 1) SQL Server Management Studio → 개체 탐색기 → 보안 → 로그인 |
| 3 | 2) 계정별 오른쪽 마우스 → 속성 → 서버 역할에서 sysadmin 권한 해제 |

| 플랫폼 | MS-SQL |
| 점검영역 | 계정 관리 |

### 항목 설명

MS-SQL 설치 시, sa 계정은 sysadmin 권한을 가지며 디폴트로 생성된다. sa 계정의 패스워드가 설정되어 있지 않다면 악의적인 사용자가 해당 계정을 통해 데이터베이스에 접근하여 데이터를 열람, 삭제, 수정하는 위험이 존재한다. 따라서 sa 계정 패스워드를 설정해야 한다.

### 진단 기준

| 판정 | 조건 |
|---|---|
| 양호 조건 | sa 계정에 패스워드가 설정된 경우 |
| 취약 조건 | sa 계정에 패스워드가 설정되어 있지 않은 경우 |

## GUIDE-MSS-004 Guest 계정 사용 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK4 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-MSS-004 |
| 플랫폼 | MS-SQL |
| 점검영역 | 계정 관리 |

### 항목 설명

SQL의 모든 사용자가 접근 가능한 Guest 계정은 기본 설정으로 활성화되어 있으므로 모든 데이터베이스에서 Guest 권한을 제거해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 데이터베이스에 Guest 계정이 활성화되어 있지 않은 경우 |
| 취약 조건 | 데이터베이스에 Guest 계정이 활성화되어 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 데이터베이스에 부여된 Guest 계정 확인 |
| 2 | 1) SQL Server Management Studio → 개체 탐색기 → 데이터베이스 |
| 3 | 2) 데이터베이스 별 → 보안 → 사용자 → guest 계정 오른쪽 마우스 → 패싯 |
| 4 | 3) 패싯 속성에서 DasDBAccess 설정 값 |
| 5 | ※ master, tempdb 데이터베이스에 Guest 계정이 디폴트로 활성화되어 있으며 삭제가 불가능함 (Microsoft SQL Server 2022 기준) |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 데이터베이스에 존재하는 Guest 계정 비활성화 |
| 2 | 1) SQL Server Management Studio → 새 쿼리 |
| 3 | 2) USE [해당 데이터베이스] |
| 4 | 3) REVOKE connect FROM guest; |

## GUIDE-MSS-005 Regisrtry Procedure Permission 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-MSS-005 |
| 플랫폼 | MS-SQL |
| 점검영역 | 보안 설정 |

### 항목 설명

레지스트리 확장 저장 프로시저를 이용하면 Windows 레지스트리에 액세스할 수 있다. 레지스트리에는 SQL에 대한 구성 정보가 들어있으며 원격 또는 로컬 시스템에 대한 암호가 포함되어 있을 수 있으므로 악의적인 사용자가 windows 레지스트리를 이용하여 서버 및 데이터베이스에 손상 및 비 인가된 접근을 할 위험이 존재한다. 따라서 시스템 확장 저장 프로시저 제한 목록의 프로시저를 제한해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 제한이 필요한 시스템 확장 저장 프로시저들이 DBA 외 guest/public에게 부여되어 있지 않은 경우 |
| 취약 조건 | 제한이 필요한 시스템 확장 저장 프로시저들이 DBA 외 guest/public에게 부여되어 있는 경우 |

## GUIDE-MSS-006 xp_cmdshell 사용 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK6 -->

| 항목 | 내용 |
|---|---|

| 플랫폼 | MS-SQL |
| 점검영역 | 보안 설정 |

### 항목 설명

MS-SQL이 제공 중인 확장 프로시저 중에 서버의 유지 관리 목적으로 사용되고 있는 확장 프로시저들이 해킹 툴에서 자주 이용되고 있으며 특히 중국에서 제작된 해킹 툴에서 자주 이용되고 있으므로 불필요한 경우 반드시 제거해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR6 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | xp_cmdshell이 제한되어 있는 경우 |
| 취약 조건 | xp_cmdshell이 제한되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 새 쿼리를 통해 프로시저 확인 |
| 2 | 1) SQL Server Management Studio → 새쿼리 |
| 3 | 2) SELECT name, value FROM sys.configurations WHERE name = ‘xp_cmdshell’; |
| 4 | ※ xp_cmdshell 값이 0(false)일 경우 양호 |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT6-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 개체 탐색기를 통해 프로시저 확인 |
| 2 | 1) SQL Server Management Studio → 개체 탐색기 → 컴퓨터 이름 → 오른쪽 마우스 → 패싯 → 일반 |
| 3 | 2) XPCmdShellEnabled 값 확인 |
| 4 | ※ XPCmdShellEnable 값이 false일 경우 양호 |

| 3 | 2) (실패한 로그인만/성공한 로그인만/실패한 로그인과 성공한 로그인 모두) 이 3가지 중 1가지가 설정되어 있는지 확인 |
