## GUIDE-PCL-001 root 계정의 원격 접속 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PCL-001 |
| 플랫폼 | PC(Linux) |
| 점검영역 | 계정 관리 |

### 항목 설명

root 계정은 운영체제의 모든 기능 설정 및 변경이 가능하며(프로세스, 커널 변경 등) 비인가자가 외부 원격 접속을 통해 root 계정을 탈취할 경우 시스템 장악, 중요 데이터의 위·변조, 정보 유출 등 침해사고가 발생할 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 원격 터미널 서비스를 사용하지 않거나, 사용 시 root 직접 접속을 차단한 경우 |
| 취약 조건 | 원격 터미널 서비스 사용 시 root 직접 접속을 허용한 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • root 접속 가능 여부 확인 (SSH 사용 시) |
| 2 | - /etc/ssh/sshd_config 파일 내 PermitRootLogin 설정 확인 |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • root 접속 가능 여부 확인 (Telnet 사용 시) |
| 2 | - /etc/securetty 파일 내 pts/0 ~ pts/x 설정 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • root 접속 차단 (SSH 사용 시) |
| 2 | - vi 편집기를 이용하여 /etc/ssh/sshd_config 파일 열기 |
| 3 | - PermitRootLogin No로 변경 |

<!-- @block name=remediation method_no=2 cols=step,text id=RM-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • root 접속 차단 (Telnet 사용 시) |
| 2 | - “/etc/securetty” 파일에서 pts/0 ~ pts/x 설정 제거 또는 주석 처리 |
| 3 | - “/etc/pam.d/login” 파일 내 auth required /lib/security/pam_securetty.so 삽입 또는 주석 제거 (파일이 없다면 생성해야 함) |

### 비고

￭ SSH를 사용하는 경우 PermitRootLogin No 설정 앞에 주석(#)이 제거되어 있어야 함

## GUIDE-PCL-002 패스워드의 주기적 변경

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PCL-002 |
| 플랫폼 | PC(Linux) |
| 점검영역 | 계정 관리 |

### 항목 설명

패스워드 최대 사용 기간을 설정하지 않은 경우 비인가자가 각종 공격(무작위 대입 공격, 사전 대입 공격 등)을 장기적으로 시도할 수 있으며, 패스워드 변경 주기에 비례하여 패스워드 유출 확률이 증가할 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 패스워드 최대 사용 기간이 90일(12주) 이하로 설정되어 있는 경우 |
| 취약 조건 | 패스워드 최대 사용 기간이 90일(12주) 이하로 설정되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 패스워드 최대 사용 기간 설정 확인 |
| 2 | - /etc/login.defs 파일 내 PASS_MAX_DAYS 설정 확인 |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT2-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 각 계정별 패스워드 최대 사용 기간 설정 확인 |
| 2 | - chage –l [계정명] &#124; grep –i maximum |

<!-- @code id=CMD-001 block=check_steps language=sh -->

```sh
chage -l [계정명] | grep -i maximum
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 패스워드 최대 사용 기간 90일로 설정 |
| 2 | - vi 편집기를 이용하여 /etc/login.defs 파일 열기 |
| 3 | - PASS_MAX_DAYS 90 (단위: 일) 삽입 |

<!-- @block name=remediation method_no=2 cols=step,text id=RM2-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 각 계정별 패스워드 최대 사용 기간 90일로 설정 |
| 2 | - chage –E –I –M 90 [계정명] |

### 비고

/etc/login.defs 설정을 변경할 경우, 변경 시점 이후부터 생성되는 계정에만 적용됨

## GUIDE-PCL-003 기관 보안 정책과 패스워드 정책 일치

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PCL-003 |
| 플랫폼 | PC(Linux) |
| 점검영역 | 계정 관리 |

### 항목 설명

패스워드 복잡도 설정을 점검하여 해당 기관의 보안 정책에 적합하게 패스워드 정책이 설정되어 있는지 확인하고, 비인가자의 패스워드 추측 공격(무작위 대입 공격, 사전 대입 공격 등)에 대한 대비가 되어있는지 확인한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 기관 정책에 맞게 패스워드 복잡도 설정이 적용되어 있는 경우 |
| 취약 조건 | 기관 정책에 맞게 패스워드 복잡도 설정이 적용되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 비밀번호 복잡도 설정 확인 |
| 2 | - cat /etc/pam.d/common-password (또는 /etc/security/pwquality.conf) |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 비밀번호 복잡도 설정 정책 적용 |
| 2 | - /etc/pam.d/common-password (또는 /etc/security/pwquality.conf) 파일에서 아래와 같이 설정 |
| 3 | # vi /etc/pam.d/common-password |
| 4 | password requisite pam_pwquality.so |
| 5 | enforce_for_root retry=3 minlen=8 lcredit=-1 |
| 6 | ucredit=-1 dcredit=-1 ocredit=-1 |

<!-- @block name=remediation method_no=2 cols=step,text id=RM3-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • RHEL 계열의 경우 /etc/pam.d/system-auth 파일에도 복잡도 설정이 가능하며 위 파일에 enforce_for_root 설정 적용 필요 |

### 비고

￭ lcredit : 포함되어야 할 알파벳 소문자의 수( ‘-‘ 로 입력하면 최소) ￭ ucredit : 포함되어야 할 알파벳 대문자의 수( ‘-‘ 로 입력하면 최소) ￭ dcredit : 포함되어야 할 숫자 수( ‘-‘ 로 입력하면 최소) ￭ ocredit : 포함되어야 할 특수문자 수( ‘-‘ 로 입력하면 최소) ￭ minclass : 각기 다른 문자의 조합 수( 4로 설정한 경우 숫자, 대·소문자, 특수문자 모두 포함되어야 함) ￭ enforce_for_root: root 계정 또한 정책 적용 ※ 다음 각 항목의 문자 종류 중 2종류 이상을 조합하여 최소 10자리 이상 또는, 3종류 이상을 조합하여 최소 8자리 이상의 길이로 구성 가. 영문 대문자 26개 나. 영문 소문자 26개 다. 숫자 10개 라. 특수문자 32개

## GUIDE-PCL-004 자동 로그인 비활성화

## GUIDE-PCL-008 계정 및 패스워드 파일 소유자 및 권한 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK8 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PCL-008 |
| 플랫폼 | PC(Linux) |
| 점검영역 | 보안 관리 |

### 항목 설명

/etc/passwd 파일은 사용자의 ID, 패스워드(보안상 ‘x'로 표시), UID, GID, 홈 디렉토리, shell 정보를 담고 있는 중요 파일로, 이 파일이 노출되면 보안상 심각한 문제를 발생할 수 있어 관리자 이외의 사용자는 접근 제한이 필요하다. /etc/shadow 파일은 암호화된 패스워드와 패스워드 설정 정책을 담고 있는 중요 파일로 이 파일이 노출되면 보안상 심각한 문제를 발생할 수 있어 소유자 외의 사용자는 접근 제한이 필요하다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR8 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 불필요한 일반 사용자의 쓰기 권한이 부여되어 있지 않고, 소유자가 root인 경우 |
| 취약 조건 | 불필요한 일반 사용자의 쓰기 권한이 부여되어 있지 않고, 소유자가 root가 아닌 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT8 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 계정 및 패스워드 파일 설정 확인 |
| 2 | - ls –l /etc/passwd |
| 3 | - ls –l /etc/shadow |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM8 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 계정 및 패스워드 파일 권한 변경 |
| 2 | - chmod 644 /etc/passwd |
| 3 | - chmod 400 /etc/shadow |

<!-- @block name=remediation method_no=2 cols=step,text id=RM8-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 소유자를 root로 변경 |
| 2 | - chown root /etc/passwd |
| 3 | - chown root /etc/shadow |
