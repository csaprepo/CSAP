## GUIDE-PCM-001 패스워드 주기적 변경

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PCM-001 |
| 플랫폼 | PC(MAC) |
| 점검영역 | 계정 관리 |

### 항목 설명

계정의 패스워드를 주기적으로 변경하지 않고 오랜 기간 사용하는 경우 계정 패스워드가 외부로 유출될 수 있으며 관리자 계정의 패스워드가 유출될 시 자료 유출 등 심각한 사고 발생 가능성이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 암호 만료 기간이 90일(129600분) 이하로 설정된 경우 |
| 취약 조건 | 암호 만료 기간이 설정되어 있지 않거나 90일(129600분)을 초과하는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • 명령 프롬프트에서 확인 |
| 2 | 1) # pwpolicy getglobalpolicy 명령어 실행 |
| 3 | 2) “maxMinutesUntilChangePassword” 설정이 129600(분 단위) 이하로 적용되어 있는지 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • 터미널에서 최대 암호 사용 기간 설정 |
| 2 | 1) 패스워드 최대 사용 기간 설정 |
| 3 | # sudo pwpolicy -setglobalpolicy “maxMinutesUntilChangePassword=[암호 만료 기간(분 단위)]” 명령어 실행 |
| 4 | 2) 패스워드 최대 사용기간 설정 확인 |
| 5 | # pwpolicy getglobalpolicy 명령어 실행을 통해 최대 암호 사용 기간 적용 여부 확인 |

## GUIDE-PCM-002 기관 보안 정책과 패스워드 정책 일치

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PCM-002 |
| 플랫폼 | PC(MAC) |
| 점검영역 | 계정 관리 |

### 항목 설명

대부분 환경에서 3종류(영문‧숫자‧특수문자) 조합의 경우 8자리 패스워드 사용, 2종류(영문‧숫자) 조합의 경우 10자리 암호 사용을 권고하고 있다. 패스워드 정책에 적합하게 패스워드가 설정된 경우 무작위 대입 공격(Brute Force Attack)이나 패스워드 추측 공격(Password Guessing)에 대한 대비가 가능하다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 최소 암호 길이가 해당 기관의 보안 정책을 반영하여 설정되어있는 경우 |
| 취약 조건 | 암호를 사용하지 않거나, 추측하기 쉬운 문자 조합으로 이루어진 짧은 자릿수의 패스워드를 사용하고 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 터미널에서 최소 암호 길이 확인 |
| 2 | 1) # pwpolicy getglobalpolicy 명령어 실행 |
| 3 | 2) “minChar” 설정이 8자리 이상으로 적용되어 있는지 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 터미널에서 최소 암호 길이 설정 |
| 2 | 1) # pwpolicy setglobalpolicy “minChar=[패스워드 길이]” 명령어 실행 |
| 3 | 2) # pwpolicy getglobalpolicy 명령어 실행을 통해 적용 여부 확인 |

### 비고

￭ 패스워드 설정 기준 1. 영문, 숫자, 특수문자를 조합하여 계정명과 상이한 8자 이상의 패스워드 설정 (다음 각 항목의 문자 종류 중 2종류 이상을 조합하여 최소 10자리 이상 또는, 3종류 이상을 조합하여 최소 8자리 이상의 길이로 구성) 가. 영문 대문자(26개) 나. 영문 소문자(26개) 다. 숫자(10개) 라. 특수문자(32개) 2. 패스워드는 비인가자에 의한 추측이 어렵도록 다음의 사항을 반영하여 설계 (1) Null(공백) 패스워드 사용 금지 (2) 문자 또는 숫자만으로 구성 금지 (3) 사용자 ID와 동일하거나 유사하지 않은 패스워드 금지 (4) 연속적인 문자나 숫자 사용 (예) 1111, 1234, abcd) 사용 금지 (5) 주기성 패스워드 재사용 금지 (6) 전화번호, 생일과 같이 추측하기 쉬운 개인정보를 패스워드로 사용 금지 3. SAM 파일에 암호를 저장하기 위해 사용되는 LANMan 알고리즘은 8자 단위로 글자를 나누어 암호화하기 때문에 8의 배수가 되는 암호 사용을 권장 (8자로 이루어진 암호 사용 권장) 4. 아래와 같은 암호 설정 지양 Null, 계정과 동일하거나 유사한 스트링, 지역명, 부서명, 담당자명, 대표 업무명 예) root, rootroot, root123, 123root, admin, admin123, 123admin, osadmin, adminos

## GUIDE-PCM-003 Guest 계정 비활성화

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PCM-003 |
| 플랫폼 | PC(MAC) |
| 점검영역 | 계정 관리 |

### 항목 설명

MAC OS에는 Guest 계정 로그인 허용, 공유 폴더 연결 허용 설정이 존재한다. 만약 Guest 계정이 활성화되면 공유 폴더에 접근하여 중요 자료가 노출될 가능성이 존재한다

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | Guest 계정 허용 설정이 적용되지 않은 경우 |
| 취약 조건 | Guest 계정 허용 설정이 적용된 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 터미널에서 Guest 계정 허용 설정 확인 |
| 2 | 1) # defaults read /Library/Preferences/com.apple.loginwindow GuestEnabled 명령어를 실행 |
| 3 | - 출력값이 ‘0’인 경우 양호 |
| 4 | 2) # defaults read /Library/Preferences/com.apple.AppleFileServer.plist guestAccess 명령어를 실행 |
| 5 | - 출력값이 ‘0’인 경우 양호 |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT3-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 시스템 환경설정에서 Guest 계정 설정 확인 |
| 2 | 1) 시스템 환경설정 → 사용자 및 그룹 → 방문 사용자 |
| 3 | 2) 방문 사용자 설정 확인 |

### 조치 방법

## GUIDE-PCM-005 공유 폴더 제거

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PCM-005 |
| 플랫폼 | PC(MAC) |
| 점검영역 | 파일 시스템 |

### 항목 설명

MAC은 계정 생성 시 공유 폴더가 생성되며 파일 공유를 Default로 설정할 경우, 읽기 권한을 가진 계정도 파일을 복사할 수 있어 비인가자가 악의적으로 대용량 파일을 다량 복사하여 하드디스크 자원을 고갈시킬 수 있으므로 공유 폴더 사용 시 별도의 폴더를 사용하고 Everyone 권한을 제거해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 불필요한 공유 폴더가 존재하지 않는 경우 |
| 취약 조건 | 불필요한 공유 폴더가 존재하는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 터미널에서 파일 공유 활성화 확인 |
| 2 | 1) # launchctl print system &#124; egrep “smbd&#124;AppleFileServer” 명령어를 실행 |
| 3 | - “com.apple.smbd” 설정이 false인 경우, 파일 공유 활성화 상태 |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT5-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 시스템 환경설정에서 파일 공유 활성화 확인 |
| 2 | 1) 시스템 환경설정 → 공유 → 파일 공유에서 활성화 확인 |

## GUIDE-PCM-013 바이러스 백신 프로그램 설치 및 주기적 업데이트

### 항목 설명

바이러스 백신 프로그램은 바이러스, 웜 등으로부터 시스템을 보호하기 위한 중요한 보안 요소이다. 백신 프로그램을 설치해야 하며 최신 바이러스 탐지를 위하여 패턴 업데이트가 자주 발생하므로 이를 즉각적으로 업데이트하여 반영하는 것이 중요하다.

| 취약 조건 | 백신이 설치되어 있지 않거나, 최신 업데이트가 적용되어 있지 않은 경우 |

| 2 | 1) 백신 프로그램 설치 여부와 최신 Update 여부를 점검 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM13 -->

MAC OS에는 원격으로 접속하거나 명령어를 전달받아 실행하는 기능이 존재한다. 만약 원격기능을 허용할 경우 임의의 사용자에 의한 시스템 설정 변경 및 중요 정보 유출 가능성이 존재한다. 따라서 원격 기능이 불필요한 경우 해당 기능을 비활성화해야 한다.
