## GUIDE-PGS-001 불필요한 계정 제거

### 항목 설명

데이터베이스의 계정 중 인가되지 않은 계정, 퇴직자 계정, 테스트 계정 등 실질적으로 업무에 사용하지 않은 불필요한 계정들이 있는 경우 비인가자가 쉽게 데이터베이스에 접속하여 데이터를 열람, 삭제, 수정 등을 할 위험이 있다.

| 취약 조건 | DB 설치 시 Default로 생성되는 계정 및 테스트 계정, 의심스럽거나 불필요한 계정이 있는 경우 |

## GUIDE-PGS-002 취약한 패스워드 사용 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PGS-002 |
| 플랫폼 | PostgresSQL |
| 점검영역 | 보안 설정 |

### 항목 설명

패스워드가 추측이 가능하거나 null인 상태인 경우, 비인가자가 쉽게 데이터베이스에 접근할 위험이 있으며 이 경우 데이터베이스 데이터를 삭제, 변경 등의 심각한 침해 사고를 일으킬 가능성이 있으므로 패스워드 복잡도 설정을 만족하도록 패스워드를 변경해서 사용해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | null인 패스워드를 사용하지 않으며 복잡도 설정을 만족하는 경우 |
| 취약 조건 | null인 패스워드를 사용하거나 복잡도 설정을 만족하지 않는 경우 |

## GUIDE-PGS-003 불필요한 권한 제거

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PGS-003 |
| 플랫폼 | PostgresSQL |
| 점검영역 | 보안 설정 |

### 항목 설명

PostgreSQL의 Superuser는 모든 권한을 무시하고 작업을 수행할 수 있으며 Create Role은 계정을 생성하고 권한을 부여할 수 있다. 불필요한 계정에 Superuser, Create Role이 설정되어 있는 경우 비인가자가 데이터베이스에 접근하여 계정 생성 및 삭제, 데이터 열람, 수정 등을 할 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | Superuser, Create Role이 적절한 계정에 설정된 경우 |
| 취약 조건 | Superuser, Create Role이 적절하지 않은 계정에 설정된 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • psql 접속 후, 명령어로 사용자 계정 목록 조회 |
| 2 | 1) postgres=# \du |
| 3 | ※ default로 생성되는 postgres 계정은 기본적으로 Superuser, Create Role 설정 존재함 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 명령어를 통해 불필요한 권한을 제거 |
| 2 | 1) postgres=# ALTER ROLE 계정명 WITH NOSUPERUSER NOCREATEROLE; |

<!-- @block name=remediation method_no=2 cols=step,text id=RM3-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 권한 제거 확인 |
| 2 | 1) postgres=# \du |

## GUIDE-PGS-004 Public schema 사용 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK4 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PGS-004 |
| 플랫폼 | PostgresSQL |
| 점검영역 | 보안 설정 |

### 항목 설명

PosgreSQL에서 DB를 생성하는 경우에 Public Schema가 자동으로 생성된다. 별도의 schema를 생성하지 않고 table을 만드는 경우, 기본적으로 Public Schema 안에 생성된다. Public Schema는 모든 개체에서 접근이 가능하므로 정보 유출, 자원 고갈 등의 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | Public Schema에 소유주와 특정 계정만이 접근 가능한 경우 |
| 취약 조건 | Public Schema에 모든 계정이 접근 가능한 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • psql 접속 후, 명령어로 확인 |
| 2 | 1) postgres=# \dn+ |
| 3 | ※ +뒤의 ‘=UC/postgres‘가 존재한다면 모든 계정에서 Public Schema에 접근이 가능하다는 의미 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 명령어를 통해 Public Schema에 public 권한 제거 (예시) |
| 2 | 1) postgres=# REVOKE all ON schema public from PUBLIC; |

<!-- @block name=remediation method_no=2 cols=step,text id=RM4-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 모든 계정 접근 제한 확인 |
| 2 | 1) postgres=# \dn+ |

### 비고

※ PostgreSQL v15 이상에서는 postgres가 아닌 Public Schema에 현재 데이터베이스의 실제 소유자를 포함하는 pg_database_owner 접근 권한이 디폴트로 부여됨

## GUIDE-PGS-007 안전한 암호화 알고리즘 사용

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK7 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PGS-007 |
| 플랫폼 | PostgresSQL |
| 점검영역 | 보안 설정 |

### 항목 설명

SHA-1 암호화 알고리즘의 취약점이 발견됨에 따라 SHA-1 이하의 암호화 알고리즘을 사용하지 않고 SHA-256 이상의 안전한 암호화 알고리즘을 사용해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR7 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | SHA-256 이상의 암호화 알고리즘을 사용하는 경우 |
| 취약 조건 | SHA-256 이상의 암호화 알고리즘을 사용하지 않는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT7 -->

| 순서 | 절차 |
|---:|---|
| 1 | • psql 접속 후, 계정별 암호화 알고리즘 확인 |
