## GUIDE-IFL-001 인증사용 여부

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-IFL-001 |
| 플랫폼 | InfluxDB |
| 점검영역 | 보안 설정 |

### 항목 설명

InfluxDB의 실행 데몬인 influxd를 실행할 때, 인증 설정을 사용하지 않으면 인증 없이 접근이 가능하게 되므로 비인가된 사용자가 데이터베이스에 접근하여 악의적인 행위를 할 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 인증 여부가 활성화되어 있는 경우 |
| 취약 조건 | 인증 여부가 비활성화되어 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | [InfluxDB v1] |
| 2 | • influxdb.conf 파일 내 auth-enabled 설정 확인 |
| 3 | # cat /etc/influxdb/influxdb.conf |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | [InfluxDB v2] |
| 2 | • v2에서는 기본적으로 인증 기능을 사용 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | [InfluxDB v1] |
| 2 | • influxdb.conf 파일 내 auth-enabled 설정 변경 |
| 3 | # vi /etc/influxdb/influxdb.conf |
| 4 | auth-enabled = true |

## GUIDE-IFL-002 사용자 및 권한 관리

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 점검코드 | GUIDE-IFL-002 |
| 플랫폼 | InfluxDB |
| 점검영역 | 보안 설정 |

### 항목 설명

DB 관리나 운용에 사용하지 않는 불필요한 계정이나 부적절한 권한이 존재할 경우 비인가자가 불필요한 계정을 이용하여 DB에 접근하여 데이터를 열람, 삭제, 수정할 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 계정 정보를 확인하여 불필요한 계정이 없는 경우 |
| 취약 조건 | 인가되지 않은 계정, 퇴직자 계정, 테스트 계정 등 불필요한 계정이 존재하는 경우 |

## GUIDE-IFL-003 HTTPS 프로토콜 활성화

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-IFL-003 |
| 플랫폼 | InfluxDB |
| 점검영역 | 보안 설정 |

### 항목 설명

HTTP 프로토콜은 암호화가 되지 않는 평문 통신으로, 중간에 패킷을 가로채 DB 정보가 노출될 수 있으므로, HTTPS를 통해 암호화 통신이 되어있는지 확인한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | HTTPS 프로토콜이 활성화되어 있는 경우 |
| 취약 조건 | HTTPS 프로토콜이 비활성화되어 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | [InfluxDB v1] |
| 2 | • influxdb.conf 파일 내 https-enabled 설정 확인 |
| 3 | # cat /etc/influxdb/influxdb.conf |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT3-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | [InfluxDB v2] |
| 2 | • config 파일 및 실행 데몬 옵션값 tls-key, tls-cert 설정 확인 |
| 3 | # cat /etc/influxdb/config.toml |
| 4 | - tls-key, tls-cert 값 확인 |
| 5 | # ps –ef &#124; grep influxd |

<!-- @code id=CMD-001 block=check_steps language=sh -->


### 조치 방법

## GUIDE-IFL-004 IP 접근 권한 설정

<!-- @block name=control keys=control_id,asset,category id=CK4 -->

| 항목 | 내용 |

| 점검영역 | 보안 설정 |

### 항목 설명

인가된 IP만 접근 가능하도록 설정되어 있지 않은 경우, 비인가 사용자가 해당 데이터베이스에 접근할 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 인가된 IP만 접근 가능하도록 설정되어 있는 경우 |
| 취약 조건 | 비인가된 IP가 접근 가능하도록 설정되어 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • IP 접근제어 확인 |
| 2 | - iptables 설정 확인 |
| 3 | # iptables –L |
| 4 | - /etc/hosts.deny , allow 설정 확인 |
| 5 | # cat /etc/hosts.allow |
| 6 | # cat /etc/hosts.deny |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • iptables 설정 |

<!-- @block name=remediation method_no=2 cols=step,text id=RM4-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • /etc/hosts.deny, allow 설정 |
| 2 | # vi /etc/hosts.deny |
| 3 | # vi /etc/hosts.allow |

### 비고

※ Server의 IP 접근 정책(iptables, tcpwrapper, firewalld 등)이 부재한 경우, 별도의 방화벽 정책 확인 필요

## GUIDE-IFL-005 패스워드 파일 권한 변경
