## GUIDE-DKR-001 도커 최신 보안 패치 적용

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-DKR-001 |
| 플랫폼 | Docker |
| 점검영역 | Host 설정 |

### 항목 설명

Docker 최신 보안 패치를 적용함으로써 Docker 소프트웨어 취약점을 완화할 수 있다. 공격자가 권한을 획득하거나 권한 상승을 시도할 때 보안 취약점을 이용할 수 있으며 그에 따라 권한 상승, 비인가 접근, 기타 보안 침해로 이어질 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 최신 보안 패치를 적용하고 있는 경우 |
| 취약 조건 | 최신 보안 패치를 적용하고 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • 현재 버전 확인 |
| 2 | 1) # docker version |
| 3 | 2) Ubuntu, Debian 패키지 버전 확인 |
| 4 | # dpkg –l &#124; grep docker.io |
| 5 | 3) CentOS 패키지 버전 확인 |
| 6 | # rpm –qa &#124; grep docker.io |

<!-- @code id=CMD-001 block=check_steps language=sh -->

```sh
dpkg -l | grep docker.io
rpm -qa | grep docker.io
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • 보안 패치 적용 |
| 2 | 1) 보안 취약점이 존재하지 않는 버전으로 보안패치를 적용해야 함 |
| 3 | ※ 최신 버전을 사용하도록 권고하고 있으나 시스템 운영상 적용이 어려운 경우 최신이 아닌 취약점이 존재하지 않는 버전도 허용하고 있음 |

## GUIDE-DKR-002 도커 그룹에 불필요한 사용자 제거

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-DKR-002 |
| 플랫폼 | Docker |
| 점검영역 | Host 설정 |

### 항목 설명

Docker 데몬은 root 권한이 필요하며 Docker 그룹에 추가된 사용자는 root 권한을 부여받게 된다. 따라서 컨테이너를 실행하고 호스트의 root 디렉터리를 컨테이너에 매핑 할 수 있어 컨테이너는 제한 없이 호스트 파일 시스템을 변경할 수 있는 위험이 존재한다. 따라서 도커 그룹에 불필요한 사용자를 제거하여 root 권한 부여를 제한해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 도커 그룹에 불필요한 사용자가 존재하지 않는 경우 |
| 취약 조건 | 도커 그룹에 불필요한 사용자가 존재하는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 도커 그룹에 속한 사용자 계정 조회 |
| 2 | 1) # cat /etc/group &#124; grep docker |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT2-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 도커 그룹 이름이 dockerroot인 경우 |
| 2 | 1) 아래의 두 명령어 모두 입력하여 확인 |
| 3 | # cat /etc/group &#124; grep docker |
| 4 | # cat /etc/group &#124; grep root |

<!-- @code id=CMD-002 block=check_steps language=sh -->

```sh
cat /etc/group | grep docker
cat /etc/group | grep root
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 도커 그룹에서 불필요한 사용자 제거 |
| 2 | 1) # vi /etc/group 입력 후, 불필요한 사용자 계정 제거 |

<!-- @block name=remediation method_no=2 cols=step,text id=RM2-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 도커 그룹 이름이 dockerroot인 경우 |
| 2 | 1) root 그룹, dockerroot 그룹 모두 불필요한 사용자 계정 제거 |
| 3 | # vi /etc/group |

## GUIDE-DKR-032 호스트의 user namespaces 공유 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK32 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-DKR-032 |
| 플랫폼 | Docker |
| 점검영역 | 컨테이너 런타임 |

### 항목 설명

user namespaces는 컨테이너 내부의 루트 프로세스가 컨테이너 외부의 루트가 아닌 프로세스에 매핑되도록 한다. 따라서 호스트의 use namespaces을 컨테이너와 공유하면 호스트의 사용자와 컨테이너의 사용자가 분리되지 않는다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR32 -->

|---|---|

| 취약 조건 | 호스트의 user namespace를 컨테이너와 공유하고 있는 경우 |
