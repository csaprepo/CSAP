## GUIDE-STG-001 root 계정 원격 접속 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-STG-001 |
| 플랫폼 | 스토리지 |
| 점검영역 | 계정 관리 |

### 항목 설명

root 계정으로 직접 로그인을 하도록 허용하면 불법적인 침입자의 목표가 될 수 있으므로 root 계정 원격 접속을 금지해야 한다. 또한, 일반 사용자 계정 접속 후 관리자 계정으로의 변경 시 로그가 남지만, 관리자 계정으로 바로 접속하는 경우 어느 사용자가 접속했는지 알 수 없으므로 문제 발생 시 책임소재를 파악할 수 없다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | root 계정의 원격 접속이 제한되어 있는 경우 |
| 취약 조건 | root 계정의 원격 접속이 제한되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • root 계정의 원격 접속 제한 설정 |
| 2 | 1) 인터뷰를 통해 root 계정에 원격으로 접속 가능한지 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • root 계정의 원격 접속 제한 설정을 적용 |

## GUIDE-STG-002 패스워드 복잡도 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-STG-002 |
| 플랫폼 | 스토리지 |
| 점검영역 | 계정 관리 |

### 항목 설명

사용자 계정(root 및 일반 계정 모두)의 암호 설정 시, 일반적으로 유추하기 쉬운 암호를 설정하여, 비인가 사용자의 시스템 접근을 허용할 수 있다. 따라서 영문(대문자, 소문자), 숫자, 특수문자가 혼합된 8자리 이상의 패스워드로 설정하여 공격자가 추측하기 어려운 패스워드를 사용하거나 영문(대문자, 소문자), 숫자, 특수문자 중 2가지가 혼합된 10자리 이상의 패스워드로 설정해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 패스워드를 영문, 숫자, 특수문자 중 3가지 조합으로 8자리 이상 또는 2가지 조합으로 10자리 이상 사용하여 복잡하게 설정한 경우 |
| 취약 조건 | 패스워드가 존재하지 않거나 패스워드를 영문, 숫자, 특수문자를 혼합하지 않거나 8자리 미만으로 설정한 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 패스워드 복잡도 설정 만족 |
| 2 | 1) 인터뷰를 통해 패스워드가 복잡도 설정을 만족하고 있는지 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 패스워드 복잡도 설정 만족 |
| 2 | 1) 패스워드 복잡도 기준을 만족하도록 패스워드를 설정 |

## GUIDE-STG-003 계정 잠금 임계값 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-STG-003 |
| 플랫폼 | 스토리지 |
| 점검영역 | 계정 관리 |

### 항목 설명

침입자에 의한 패스워드 무작위 대입 공격(Brute Force Attack)이나 패스워드 추측 공격(Password Guessing) 발생 시 암호입력 실패 횟수를 적정하게 제한함으로 자동공격을 차단하고 공격 시간을 지체시켜 패스워드 유출 위험을 줄일 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 패스워드 입력 횟수를 5회 이하로 제한한 경우 |
| 취약 조건 | 패스워드 입력 횟수를 설정하지 않거나, 5회 초과로 제한한 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 계정 잠금 임계값 설정 |
| 2 | 1) 인터뷰를 통해 계정 잠금 임계값 설정을 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 계정 잠금 임계값 설정 |
| 2 | 1) 계정 잠금 임계값을 5회 이하로 설정 |

## GUIDE-STG-004 패스워드 최대 사용 기간 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK4 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-STG-004 |
| 플랫폼 | 스토리지 |
| 점검영역 | 계정 관리 |

### 항목 설명

패스워드 최대 사용 기간을 설정하지 않은 경우, 일정 기간 경과 후에도 유출된 패스워드로 접속이 가능하다. 악의적인 사용자로부터 무분별한 접속을 차단하기 위해 패스워드 최대 사용 기간을 설정하여 주기적으로 변경해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 보안 정책에 따른 최대 사용 기간(90일 이내)이 설정되어 있는 경우 |
| 취약 조건 | 보안 정책에 따른 최대 사용 기간이 설정되어 있지 않거나, 90일 초과인 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 패스워드 최대 사용 기간 설정 확인 |
| 2 | 1) 인터뷰를 통해 패스워드 최대 사용 기간을 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 패스워드 최대 사용 기간 설정 |
| 2 | 1) 패스워드 최대 사용 기간을 90일 이하로 설정 |

## GUIDE-STG-005 불필요한 계정 제거

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-STG-005 |
| 플랫폼 | 스토리지 |
| 점검영역 | 계정 관리 |

### 항목 설명

인가되지 않은 계정, 퇴직자 계정, 테스트 계정 등 실질적으로 업무에 사용하지 않은 불필요한 계정들이 있는 경우 비인가자가 쉽게 스토리지에 접속하여 데이터를 열람, 삭제, 수정할 위험이 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | Default로 생성되는 계정 및 테스트 계정, 의심스럽거나 불필요한 계정이 없는 경우 |
| 취약 조건 | Default로 생성되는 계정 및 테스트 계정, 의심스럽거나 불필요한 계정이 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 불필요한 계정 확인 |
| 2 | 1) 인터뷰를 통해 계정 목록을 확인하고 각 계정의 사용 목적을 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 불필요한 계정 제거 |
| 2 | 1) 불필요하거나 의심스러운 계정, 테스트 계정, 디폴트 계정인 경우 해당 계정을 제거 |
