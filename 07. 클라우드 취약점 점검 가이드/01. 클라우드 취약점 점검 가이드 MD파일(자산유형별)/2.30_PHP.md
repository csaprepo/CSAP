## GUIDE-PHP-001 오류 메시지 노출

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PHP-001 |
| 플랫폼 | PHP |
| 점검영역 | 보안설정 |

### 항목 설명

소스 코드, 예외 처리, 시스템 콜, API 함수 호출 등 오류가 발생한 경우 실행 환경, 개발 정보, 사용자 관련 데이터에 대한 민감한 정보를 포함하는 오류 메시지가 노출될 수 있다. PHP는 display_errors 설정이 Off로 설정된 경우 오류 메시지가 웹 페이지에 노출되지 않는다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | display_errors 항목이 Off로 설정된 경우 |
| 취약 조건 | display_errors 항목이 On으로 설정된 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • PHP 설정 파일 조회 |
| 2 | 1) # cat /[PHP 설치 디렉터리]/php.ini &#124; grep display_errors |
| 3 | ※ default 설정 : Off |

<!-- @code id=CMD-001 block=check_steps language=sh -->

```sh
cat /[PHP 설치 디렉터리]/php.ini | grep display_errors
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • PHP 설정 파일에서 수정 |
| 2 | 1) # vi /[PHP 설치 디렉터리]/php.ini |
| 3 | display_errors = Off |

## GUIDE-PHP-002 불필요한 헤더 정보 노출

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PHP-002 |
| 플랫폼 | PHP |
| 점검영역 | 보안설정 |

### 항목 설명

HTTP 프로토콜을 이용할 경우 간혹 HTTP 헤더에 PHP 정보가 노출되어 공격자에게 정보를 제공한다. 공격자는 노출된 헤더 정보(운영체제, 웹 서버, PHP 버전 등)를 이용하여 추가 공격을 진행할 수 있으므로, PHP 옵션 중 expose_php를 Off로 설정하여 HTTP 헤더에 정보가 노출되지 않도록 설정해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | expose_php가 Off로 설정된 경우 |
| 취약 조건 | expose_php가 On으로 설정된 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • PHP 설정 파일 조회 |
| 2 | 1) # cat /[PHP 설치 디렉터리]/php.ini &#124; grep expose_php |

<!-- @code id=CMD-002 block=check_steps language=sh -->

```sh
cat /[PHP 설치 디렉터리]/php.ini | grep expose_php
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • PHP 설정 파일에서 수정 |
| 2 | 1) # vi /[PHP 설치 디렉터리]/php.ini |
| 3 | expose_php = Off |

## GUIDE-PHP-003 외부 URL 파일 인클루드 비활성화

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PHP-003 |
| 플랫폼 | PHP |
| 점검영역 | 보안설정 |

### 항목 설명

웹 서버에 파일을 참조하는 파라미터가 존재할 경우, 외부 URL을 입력한다면 *RFI(Shell 코드 및 악성코드를 실행) 취약점이 발생할 수 있다. 이러한 문제점을 해결하기 위해 PHP 옵션 중 allow_url_fopen 설정이 존재하는데, 해당 설정을 Off로 설정하여 외부 파일을 참조하지 못하도록 설정하는 것을 권고한다. * RFI(Remote File Inclusion): 공격자가 입력한 URL을 서버가 참조하여 실행하는 취약점

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | allow_url_fopen이 Off로 설정된 경우 |
| 취약 조건 | allow_url_fopen이 On으로 설정된 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • PHP 설정 파일 조회 |
| 2 | 1) # cat /[PHP 설치 디렉터리]/php.ini &#124; grep allow_url_fopen |

<!-- @code id=CMD-003 block=check_steps language=sh -->

```sh
cat /[PHP 설치 디렉터리]/php.ini | grep allow_url_fopen
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • PHP 설정 파일에서 수정 |
| 2 | 1) # vi /[PHP 설치 디렉터리]/php.ini |
| 3 | expose_php = Off |

## GUIDE-PHP-004 불필요한 명령어 사용 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK4 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PHP-004 |
| 플랫폼 | PHP |
| 점검영역 | 보안설정 |

### 항목 설명

PHP 페이지 중 명령어를 입력할 수 있는 페이지 또는 악성 스크립트 파일이 실행(Web Shell, 악성코드 등)될 경우 시스템 권한을 획득할 수 있다. 이러한 문제점을 해결하기 위해 PHP 옵션 중 disable_functions 항목으로 명령어를 제어하여 시스템의 피해를 최소화할 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | disable_functions에 설정(불필요한 함수)이 존재할 경우 |
| 취약 조건 | disable_functions에 설정이 존재하지 않을 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • PHP 설정 파일 조회 |
| 2 | 1) # cat /[PHP 설치 디렉터리]/php.ini &#124; grep disable_functions |
| 3 | 아무런 설정값이 존재하지 않을 경우 취약 |

<!-- @code id=CMD-004 block=check_steps language=sh -->

```sh
cat /[PHP 설치 디렉터리]/php.ini | grep disable_functions
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • PHP 설정 파일에서 수정 |
| 2 | 1) # vi /[PHP 설치 디렉터리]/php.ini |
| 3 | 예시) |
| 4 | disable_functions = exec, passthru, shell_exec, system, proc_open, popen, curl_exec, curl_multi_exec, parse_ini_file, show_source |

### 비고

※ 시스템에 영향을 주는 함수 예시 exec - 외부 프로그램을 실행하는 함수로 쉘 명령어 사용 가능 system - 외부 프로그램을 실행하는 함수로 쉘 명령어 사용 가능 shell_exec – PHP 상에서 쉘 명령어에 대한 결과값을 웹상에 출력하게 하는 함수 passthru - 외부 프로그램을 실행하고 실행되는 동안 화면을 실시간으로 출력하는 함수 phpinfo - PHP 정보(OS 및 PHP 정보 등)를 보여주는 함수 show_source – 소스 코드를 출력하는 함수 popen - 파일을 실행하고 그 결과값을 반환하는 함수 parse_ini_file - php 설정 파일을 배열에 저장하는 함수

## GUIDE-PHP-005 PHP 실행 경로 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-PHP-005 |
| 플랫폼 | PHP |
| 점검영역 | 보안설정 |

### 항목 설명

파일 업로드, 파일 다운로드 및 파일 경로를 참조 페이지가 존재할 경우, 웹 루트 상위 폴더를 벗어나 시스템 파일을 참조할 수 있는 문제점이 발생( 예) /etc/shadow, %WINNT%system32/config/SAM )한다. 웹 서버의 피해를 최소화하기 위해 PHP 옵션 open_basedir 경로를 지정하여 지정된 경로의 상위 폴더 접근을 제한할 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | open_basedir에 경로를 지정한 경우 |
| 취약 조건 | open_basedir에 경로가 지정되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • PHP 설정 파일 조회 |
| 2 | 1) # cat /[PHP 설치 디렉터리]/php.ini &#124; grep open_basedir |

<!-- @code id=CMD-005 block=check_steps language=sh -->

```sh
cat /[PHP 설치 디렉터리]/php.ini | grep open_basedir
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • PHP 설정 파일에서 수정 |
| 2 | 1) # vi /[PHP 설치 디렉터리]/php.ini |

### 비고

※ 경로를 여러 개 지정할 시 :(콜론) 구분자를 이용하여 설정 ※ 경로의 마지막에 /이 있으면 해당 디렉터리만 경로를 지정하고, /가 없는 경우에는 하위 디렉터리까지 경로를 지정함

### 항목 설명

소프트웨어의 취약점이 공개되면 소프트웨어 및 버전별 문제점을 공개하는 사이트(CCE, CWE, CVE 등)들이 존재한다. 공격자는 간단한 검색만으로 소프트웨어 또는 버전별 취약점을 확인하여 추가 공격을 진행할 수 있다. 관련하여 소프트웨어의 보안 패치를 항상 주기적으로 업데이트하여 최신화해야 한다.
