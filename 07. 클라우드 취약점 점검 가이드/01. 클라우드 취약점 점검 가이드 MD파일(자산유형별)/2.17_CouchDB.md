## GUIDE-CDB-001 불필요한 계정 제거

### 항목 설명

DB 관리나 운용에 사용하지 않는 불필요한 계정이 존재할 경우 비인가자가 불필요한 계정을 통해 DB에 접근하여 데이터를 열람, 삭제, 수정할 위험이 존재한다.

| 취약 조건 | 인가되지 않은 계정, 퇴직자 계정, 테스트 계정 등 불필요한 계정이 존재하는 경우 |

## GUIDE-CDB-002 Default 관리자 계정 이름 바꾸기

### 항목 설명

관리자 계정은 모든 시스템 리소스에 대한 권한을 가지고 있으며, Default 관리자 계정 사용 시 공격자가 예측하기 쉽고 이 계정이 탈취되거나 악용될 경우 시스템 전체에 대한 치명적인 피해가 발생할 수 있는 위험이 존재한다.

|---|---|
| 양호 조건 | Default 관리자 계정을 변경하여 사용하는 경우 |
| 취약 조건 | Default 관리자 계정을 변경하지 않고 사용하는 경우 |

| 4 | 3) admins Section에서 관리자 계정 확인(Default 관리자 계정 : admin) |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT2-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • local.ini 파일에서 관리자 계정 확인 |

<!-- @block name=figure id=FG -->

```text
[admins]
;admin = mysecretpassword
admin = -pbkdf2-c23bf522b2e878fb978e3ad2c1727c18769a5779,d868d9d9d95faea192fe26f6d0ec4ee6,10
```

## GUIDE-CDB-003 패스워드 암호화 알고리즘 확인

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-CDB-003 |
| 플랫폼 | CouchDB |
| 점검영역 | 보안 설정 |

### 항목 설명

패스워드를 취약한 암호 알고리즘으로 암호화 할 경우, 공격자가 사용자 계정의 패스워드를 해독하여, 데이터베이스에 접근 가능한 계정을 탈취할 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 암호화 알고리즘으로 PBKDF2 및 안전한 암호화 알고리즘이 적용되어 있는 경우 |
| 취약 조건 | 암호화 알고리즘으로 안전하지 않은 암호화 알고리즘이 적용되어 있는 경우 |

| 4 | 3) admins Section에서 관리자 계정에 적용된 암호화 알고리즘 확인 |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT3-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 일반 사용자 계정에 적용된 암호화 알고리즘 확인 |
| 2 | 1) http://127.0.0.1:5984/_utils/에 접속 |

## GUIDE-CDB-004 IP 접근 통제

### 항목 설명

인가된 IP만 접근 가능하도록 설정되어 있지 않은 경우, 비인가된 사용자가 해당 데이터베이스에 접근하여 보안 문제가 발생할 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 인가된 IP만 접근 가능하도록 설정되어 있는 경우 |
| 취약 조건 | 인가된 IP만 접근 가능하도록 설정되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • WEB에서 bind_address 설정 확인 |
| 2 | 1) http://127.0.0.1:5984/_utils/에 접속 |
| 3 | 2) 관리자 계정 로그인 후 Config 메뉴 선택 |
| 4 | 3) chttpd Section에서 bind_address 설정값 확인 |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT4-2 -->

| 순서 | 절차 |

## GUIDE-CDB-005 SSL 활성화

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-CDB-005 |
| 플랫폼 | CouchDB |
| 점검영역 | 보안 설정 |

### 항목 설명

SSL을 사용하지 않을 경우 데이터는 암호화되지 않아 공격자가 중간에서 네트워크를 가로채거나 도청할 수 있으며, 더 나아가 데이터가 평문으로 전송되어 중간에서 변경될 우려가 있어 데이터의 정확성이 훼손될 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | SSL이 활성화되어 있는 경우 |
| 취약 조건 | SSL이 비활성화되어 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • WEB에서 ssl 설정 확인 |
| 2 | 1) http://127.0.0.1:5984/_utils/에 접속 |
| 3 | 2) 관리자 계정 로그인 후 Config 메뉴 선택 |
| 4 | 3) ssl Section에서 enable 설정값 확인 |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT5-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • local.ini 파일에서 ssl 설정 확인 |

<!-- @block name=figure id=FG4 -->

```text
[ssl]
;enable = true
;cert_file = /full/path/to/server_cert.pem
;key_file = /full/path/to/server_key.pem
;password = somepassword
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

| 순서 | 절차 |
|---:|---|

| 3 | 2) 관리자 계정 로그인 후 Config 메뉴 선택 |
| 4 | 3) Add Option 클릭 후 ssl Section 추가 |

<!-- @block name=remediation method_no=2 cols=step,text id=RM5-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • local.ini 파일에서 ssl 설정 추가 |

## GUIDE-CDB-007 데이터베이스 사용자 정의 설정

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK7 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-CDB-007 |
| 플랫폼 | CouchDB |
| 점검영역 | 보안 설정 |

### 항목 설명

사용자를 정의하지 않거나 적절한 권한을 부여하지 않으면 모든 사용자가 데이터베이스에 대한 읽기 및 쓰기 권한을 가질 수 있으며 이로 인해 무분별한 데이터 엑세스와 수정 가능한 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR7 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 데이터베이스에 정의된 사용자 또는 Roles가 적절한 권한으로 부여되어 있는 경우 |
| 취약 조건 | 데이터베이스에 정의된 사용자 또는 Roles가 적절한 권한으로 부여되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT7 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 데이터베이스별 사용자, Roles 설정 확인 |

<!-- @block name=figure cols=item,value id=FG6 -->

| 항목 | 내용 |
|---|---|
| 주소 | 127.0.0.1:5984/_utils/#/database/security/permissions |
| 왼쪽 메뉴(security) | All Documents · Run A Query with Mango · **Permissions** · Changes · Design Documents |
| Admins | Database members can access the database. If no members are defined, the database is public. |
| **Users** | **Specify users who will have admins access to this database. · Username [Add User] · user01** |
| **Roles** | **Users with any of the following role(s) will have admins access. · Role [Add Role] · _admin** |

### 조치 방법

|---:|---|

## GUIDE-CDB-008 환경설정 파일 권한 관리

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK8 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-CDB-008 |
| 플랫폼 | CouchDB |
| 점검영역 | 보안 설정 |

### 항목 설명

환경설정 파일에 대한 취약한 접근 권한으로 공격자가 설정 파일을 변경하여 데이터베이스 서비스에 필요한 권한을 획득하여 악용 가능성을 제공하는 위험이 존재한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR8 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 환경설정 파일의 소유자 및 그룹이 관리자 계정이며 권한이 640 이하인 경우 |
| 취약 조건 | 환경설정 파일의 소유자 및 그룹이 관리자 계정이 아니거나 권한이 640 초과인 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT8 -->

| 순서 | 절차 |
|---:|---|
| 1 | • default.ini, local.ini 파일 권한 확인 |
| 2 | # ls -l [CouchDB 디렉토리]/etc/ |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT8-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • default.d, local.d 디렉토리 내부 파일 권한 확인 |
| 2 | # ls –l [CouchDB 디렉토리]/etc/default.d/ |
| 3 | # ls –l [CouchDB 디렉토리]/etc/local.d/ |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM8 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 환경 설정 파일 권한을 640으로 변경 |
| 2 | # chmod 640 [CouchDB 환경 설정 파일] |

## GUIDE-CDB-009 로그 활성화

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK9 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-CDB-009 |
| 플랫폼 | CouchDB |
| 점검영역 | 패치 및 로그 관리 |

### 항목 설명

데이터베이스의 감사기록이 기관에서 정의한 감사기록 정책에 적합하도록 설정되어 있어야 하며, 데이터베이스는 데이터, 로그와 응용프로그램에 대한 백업 정책을 수립하여야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR9 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 감사 로그 기록을 기관 정책에 맞게 시행하고 있으며, 백업 정책대로 주기적으로 백업을 하고 있는 경우 |
| 취약 조건 | 감사 로그 기록과 관련된 정책이 존재하지 않거나 정책대로 시행하고 있지 않거나 백업 정책 및 시행을 하고 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT9 -->

| 순서 | 절차 |
|---:|---|
| 1 | • WEB에서 log level 설정 확인 |
| 2 | 1) http://127.0.0.1:5984/_utils/에 접속 |
| 3 | 2) 관리자 계정 로그인 후 Config 메뉴 선택 |
| 4 | 3) log Section에서 level 설정값 확인 |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT9-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • local.ini 파일에서 log level 설정 확인 |

<!-- @block name=figure id=FG7 -->

```text
[log]
; Possible log levels:
; ;  debug
; ;  info
; ;  notice
; ;  warning, warn
; ;  error, err
; ;  critical, crit
; ;  alert
; ;  emergency, emerg
; ;  none
level = info
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM9 -->

| 순서 | 절차 |
|---:|---|
| 1 | • WEB에서 log level 변경 |
| 2 | 1) http://127.0.0.1:5984/_utils/에 접속 |
| 3 | 2) 관리자 계정 로그인 후 Config 메뉴 선택 |
| 4 | 3) log Section에서 level을 none이 아닌 다른 값으로 변경 |

<!-- @block name=remediation method_no=2 cols=step,text id=RM9-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • local.ini 파일에서 log level 변경 |
| 2 | 1) level을 none이 아닌 다른 값으로 변경 |
