## GUIDE-APA-001 웹 서비스 영역의 분리

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-APA-001 |
| 플랫폼 | Apache |
| 점검영역 | 보안 설정 |

### 항목 설명

Apache 설치 시 httdocs 디렉터리를 Document로 사용하면 공격에 이용될 수 있는 시스템 관련 정보가 노출될 수 있으므로 default DucumentRoot 경로를 변경하여 사용해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | default Document를 사용하고 있지 않은 경우 |
| 취약 조건 | default Document를 사용하고 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • 기본 디렉터리 확인 (예시) |
| 2 | 1) # cat [Apache 환경 설정 파일] &#124; grep DocumentRoot |
| 3 | ※ default : /var/www/html |
| 4 | ※ 설치 OS 및 설치 방법에 따라 환경 설정 파일의 위치가 다름 |

<!-- @code id=CMD-001 block=check_steps language=sh -->

```sh
cat [Apache 환경 설정 파일] | grep DocumentRoot
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • 기본 디렉터리 변경 |
| 2 | 1) DocumentRoot를 별도의 경로로 변경 |
| 3 | # vi [Apache 환경 설정 파일] |

## GUIDE-APA-002 불필요한 파일 제거

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-APA-002 |
| 플랫폼 | Apache |
| 점검영역 | 보안 설정 |

### 항목 설명

Apache 웹 서버 설치 시 기본으로 생성되는 매뉴얼 파일은 비인가자에게 시스템 정보 및 웹 서버 정보를 제공할 수 있으므로 제거해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 매뉴얼 파일 및 디렉터리가 제거되어 있는 경우 |
| 취약 조건 | 매뉴얼 파일 및 디렉터리가 제거되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 매뉴얼 디렉터리 존재 여부 확인 (예시) |
| 2 | 1) # cd [Apache 설치 디렉터리] |
| 3 | 2) # find . -name manual 명령어 |
| 4 | 3) httpd.conf 파일에 manual에 관련 설정 존재 여부 확인 |
| 5 | 4) # vi [Apache2 설정 디렉터리]/httpd.conf |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 매뉴얼 디렉터리 삭제 |
| 2 | 1) # rm –rf [Apache2 설치 디렉터리/manual] |
| 3 | 2) Apache 설정 파일에 매뉴얼에 관한 설정이 존재할 경우 삭제 또는 주석처리 |
| 4 | 3) # vi [Apahce 설정 파일] |

## GUIDE-APA-003 링크 사용 금지

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-APA-003 |
| 플랫폼 | Apache |
| 점검영역 | 보안 설정 |

### 항목 설명

심볼릭 링크가 활성화되어 있으면 기존의 웹 문서 이외의 파일 시스템 접근이 가능하기 때문에 편의성을 제공하는 반면 보안적으로 취약하므로 심볼릭 링크 사용을 금지해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 심볼릭 링크, aliases 사용이 제한되어 있는 경우 |
| 취약 조건 | 심볼릭 링크, aliases 사용이 제한되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |

| 2 | 1) # cat /etc/apache2/apache2.conf &#124; grep FollowSymLinks |

<!-- @block name=check_steps method_no=2 cols=step,text id=MT3-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • aliases 사용 제한 여부 확인 (예시) |
| 2 | 1) # cat [Apahce Alias 설정 파일] &#124; grep Alias |
| 3 | ※ Options FollowSymLinks 존재 = 활성화 (취약) |

<!-- @code id=CMD-002 block=check_steps language=sh -->

```sh
cat /etc/apache2/apache2.conf | grep FollowSymLinks
cat [Apahce Alias 설정 파일] | grep Alias
```

| 취약 조건 | 파일 업로드 및 다운로드 용량을 제한하고 있지 않은 경우 |

### 진단 방법

## GUIDE-APA-005 디렉터리 리스팅 제거

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-APA-005 |
| 플랫폼 | Apache |
| 점검영역 | 접근 관리 |

### 항목 설명

디렉터리 검색 기능이 활성화되어 있는 경우 외부에서 디렉터리 내 모든 파일에 접근이 가능하여 WEB 서버 구조를 파악하여 공격을 시도할 수 있으며 백업 파일이나 소스 파일 등 공개되면 안 되는 중요 파일이 노출될 수 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 디렉터리 검색 기능을 사용하지 않는 경우 |
| 취약 조건 | 디렉터리 검색 기능을 사용하는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 디렉터리 검색 기능 사용 여부 확인 |
| 2 | 1) 환경 설정 파일에서 indexes 옵션이 설정되어 있는지 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 디렉터리 검색 기능 제거 |
| 2 | 1) 환경 설정 파일 Options Indexes FollowSymLinks에서 ‘Indexes’를 제거하거나, ‘-indexex’ 옵션 설정 |
| 3 | 2) Options Indexes FollowSymLinks 주석처리 |

## GUIDE-APA-006 웹 프로세스 권한 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK6 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-APA-006 |
| 플랫폼 | Apache |
| 점검영역 | 접근 관리 |

### 항목 설명

Unix 시스템에서 apache 서버 데몬이 root 권한으로 운영되는 경우 Web Application 취약점 또는 버퍼 오버플로우로 인하여 root 권한을 획득할 수 있으므로 apache 서버 데몬이 root 권한으로 운영되지 않도록 별도 계정으로 실행해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR6 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 데몬이 root 권한으로 구동되지 않는 경우 |
| 취약 조건 | 데몬이 root 권한으로 구동되는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 웹 서버 프로세스 소유자의 권한 확인 |
| 2 | 1) # ps –ef &#124; grep apache2 |
| 3 | ※ 별도의 계정이 아닌 root 또는 root 권한으로 구동 (취약) |

<!-- @code id=CMD-004 block=check_steps language=sh -->

```sh
ps -ef | grep apache2
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • apache 데몬 user/group 변경 (예시) |
| 2 | 1) # vi [Apache 설정 디렉터리]/envvars |
| 3 | 2) APACHE_RUN_USER, APACHE_RUN_GROUP을 별도의 계정으로 변경 |
| 4 | 3) 웹 프로세스 구동 사용자 계정을 변경했을 경우, 로그인이 되지 않도록 계정에 nologin 설정 |
| 5 | # vi /etc/passwd |

### 비고

※ 설치 OS, 설치 방법에 따라 설정 파일 이름, 위치가 다름

## GUIDE-APA-007 최신 보안 패치 적용

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR7 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 최신 보안 패치를 적용한 경우 |
| 취약 조건 | 최신 보안 패치를 적용하지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT7 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 현재 버전 확인 |
| 2 | 1) # apache2 –v |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM7 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 보안 패치 적용 |
| 2 | 1) 보안 취약점이 존재하지 않는 버전으로 보안패치를 적용해야 함 |
| 3 | ※ 최신 버전을 사용하도록 권고하고 있으나 시스템 운영상 적용이 어려운 경우 최신이 아닌 취약점이 존재하지 않는 버전도 허용하고 있음 |

### 비고

※ 보안 패치를 적용할 경우, 시스템 영향도를 파악하여 충분한 테스트 후 적용 권고
