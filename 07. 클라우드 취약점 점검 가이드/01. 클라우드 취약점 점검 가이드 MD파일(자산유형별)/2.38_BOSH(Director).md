## GUIDE-BDR-001 사용자 계정 생성 여부

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-BDR-001 |
| 플랫폼 | BOSH(Director) |
| 점검영역 | 보안 설정 |

### 항목 설명

사용자 계정이 BOSH Director에 구성되어 있지 않은 경우, 디폴트 계정(admin) 자격증명을 통해 로그인이 가능하다. 따라서 BOSH Director 사용자 계정을 구성해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 사용자 계정이 존재하며 사용자 관리를 UAA 서버에 위임한 경우 |
| 취약 조건 | 사용자 계정이 존재하지 않으면서 사용자 관리를 UAA 서버에 위임하지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • 사전 구성 (Preconfigured Users) |
| 2 | 1) Director의 배포 매니페스트 파일 확인 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • 기본 구성 (사용자 계정 생성 방법) |

<!-- @block name=figure id=FG -->

```text
bosh create user some-operator
 # 새 비밀번호 입력 : ********
# 새 비밀번호 확인 : ********
#`some-operator '사용자가 생성되었습니다.
```

<!-- @block name=remediation method_no=2 cols=step,text id=RM-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 사전 구성 (설치 프로파일 내 사용자 계정 생성 방법) |
| 2 | 1) Director의 배포 매니페스트 파일 수정 및 재배포 |

### 비고

※ 사용자 관리를 UAA 서버에 위임한 경우에는 해당사항 없음(N/A)

## GUIDE-BDR-002 사용자 권한 관리

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-BDR-002 |
| 플랫폼 | BOSH(Director) |
| 점검영역 | 보안 설정 |

### 항목 설명

ID 관리를 UAA 서버에 위임한 경우, UAA는 사용자가 BOSH Director에 로그인할 때 사용자의 권한을 자동으로 확인한다. 따라서 계정별 불필요한 권한이 부여되지 않았는지 점검한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 불필요한 권한이 존재하는 경우 |
| 취약 조건 | 불필요한 권한이 존재하지 않는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 계정별 권한 확인 |
| 2 | # uaac users |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 불필요한 권한 제거 또는 불필요한 계정 제거 |
| 2 | # uaac user delete [불필요한 계정명] |

### 비고

※ BOSH Teams 계정 권한 종류

Full Admin: bosh.admin

Full Read-only: bosh.read

Stemcell uploader: bosh.stemcells.upload

Release uploader: bosh.releases.upload

Anonymous: Users with no UAA scope

## GUIDE-BDR-003 SSL 인증서 구성

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-BDR-003 |
| 플랫폼 | BOSH(Director) |
| 점검영역 | 보안 설정 |

### 항목 설명

사용자 관리를 위해 UAA를 사용하는 경우 Director 및 UAA에 대해 SSL 인증서를 구성해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | Director와 UAA 간 SSL 설정이 적용되어 있는 경우 |
| 취약 조건 | Director와 UAA 간 SSL 설정이 적용되어 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • Director 배포 매니페스트 파일 확인 |

<!-- @block name=figure id=FG2 -->

```text
...
jobs:
- name: bosh
  properties:
    director:
      ssl:
        key: |
          -----BEGIN RSA PRIVATE KEY-----
          MII...
          -----END RSA PRIVATE KEY-----
        cert: |
          -----BEGIN CERTIFICATE-----
          MII...
          -----END CERTIFICATE-----
...
```

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • SSL 인증서를 생성하고 해당 인증서를 사용하도록 Director 구성 |

## GUIDE-BDR-004 로그 활성화

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK4 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-BDR-004 |
| 플랫폼 | BOSH(Director) |
| 점검영역 | 로그 관리 및 보안 패치 |

### 항목 설명

로그 기능을 활성화함으로써 침해 사고 및 장애 발생 시 로그 자료를 분석하여 원인을 파악해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR4 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 로그가 활성화되어 있는 경우 |
| 취약 조건 | 로그가 비활성화되어 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 이벤트 로그 활성화 여부 확인 |

<!-- @block name=figure id=FG3 -->

```text
properties:
  director:
    events:
      record_events: true
```

<!-- @block name=check_steps method_no=2 cols=step,text id=MT4-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • API접근 로그 활성화 여부 확인 |
| 2 | ※ default 설정 : false |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM4 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 이벤트 로그 활성화 여부 확인 |
| 2 | 1) director.events.record_events를 true로 설정 |

<!-- @block name=remediation method_no=2 cols=step,text id=RM4-2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • API 접근 로그 활성화 여부 확인 |
| 2 | 1) director.log_access_events_to_syslog(director.log_access_events)를 true로 설정 |

### 비고

※ API 접근 로그의 경우, log_access_events_to_syslog → director.log_access_events으로 변경

## GUIDE-BDR-005 최신 보안 패치 적용

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK5 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-BDR-005 |
| 플랫폼 | BOSH(Director) |
| 점검영역 | 로그 관리 및 보안 패치 |

### 항목 설명

최신 보안 패치 및 업데이트를 수행하지 않을 경우 버전 취약점이 존재할 수 있으며 해당 취약점을 통해 시스템이 장악될 위험이 존재한다. 따라서 사용 버전에 취약점 존재 여부를 주기적으로 확인하고 최신 보안 업데이트를 수행해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR5 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 최신 보안 패치를 적용한 경우 |
| 취약 조건 | 최신 보안 패치를 적용하지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • BOSH 버전 확인 |
| 2 | # bosh env |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM5 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 최신 보안 패치 적용 시 시스템 영향도를 파악하여 충분한 테스트 후 적용 권고 |
| 2 | ※ 최신 버전을 사용하도록 권고하고 있으나 시스템 운영상 적용이 어려운 경우 최신이 아닌 취약점이 존재하지 않는 버전도 허용하고 있음 |
