## GUIDE-MYS-001 불필요한 계정 제거

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-MYS-001 |
| 플랫폼 | MY-SQL |
| 점검영역 | 계정 관리 |

### 항목 설명

데이터베이스의 계정 중 인가되지 않은 계정, 퇴직자 계정, 테스트 계정 등 업무에 사용하지 않는 불필요한 계정이 있는 경우 비인가자가 쉽게 데이터베이스에 접속하여 데이터를 열람, 삭제, 수정 등을 할 위험이 있다. 또한 DB 접속 시 지정된 IP주소만 접근 가능하도록 설정되어 있는지 확인하여 비인가자의 DB 접근을 제한해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | DB 설치 시 Default로 생성된 계정 및 테스트 계정, 의심스러운 계정, 불필요한 계정이 없는 경우 |
| 취약 조건 | DB 설치 시 Default로 생성되는 계정 및 테스트 계정, 의심스러운 계정, 불필요한 계정이 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT -->

| 순서 | 절차 |
|---:|---|
| 1 | • 사용자 계정 목록 조회 |
| 2 | 1) mysql> USE mysql; |
| 3 | 2) mysql> SELECT host, user, authentication_string FROM user; |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM -->

| 순서 | 절차 |
|---:|---|
| 1 | • 불필요한 계정 삭제 |
| 2 | 1) mysql> DELETE FROM user WHERE user=’삭제할 계정명‘; |

## GUIDE-MYS-002 취약한 패스워드 사용 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK2 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-MYS-002 |
| 플랫폼 | MY-SQL |
| 점검영역 | 계정 관리 |

### 항목 설명

패스워드가 계정명과 동일하거나 Default 패스워드를 사용하는 경우 비인가자가 쉽게 데이터베이스에 접근할 위험이 있고 접근 시, 데이터베이스 삭제, 변경 등의 심각한 침해 사고를 일으킬 가능성이 있다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR2 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 패스워드 복잡도 설정을 적용하고 있는 경우 |
| 취약 조건 | 패스워드 복잡도 설정을 적용하고 있지 않은 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • validate_password 패스워드 컴포넌트 활성화 및 복잡도 설정 확인 |
| 2 | 1) mysql> INSTALL COMPONENT ‘file://component_validate_password’; |
| 3 | 2) mysql> SHOW VARIABLES LIKE ‘validate_password%’; |
| 4 | ※ validate_password.policy가 MEDIUM 또는 STRONG으로 설정되어 있으면 양호 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM2 -->

| 순서 | 절차 |
|---:|---|
| 1 | • validate_password 패스워드 정책 (예시) |
| 2 | 1) mysql server configuration 파일에서 아래의 내용으로 수정 |
| 3 | # vi /etc/mysql/mysql.conf.d/mysqld.cnf |
| 4 | validate_password.length=8 |
| 5 | validate_password.mixed_case_count=1 |
| 6 | validate_password.number_count=1 |
| 7 | validate_password.special_char_count=1 |
| 8 | validate_password.policy=MEDIUM 또는 STRONG |
| 9 | 2) # service mysql restart |
| 10 | 3) mysql> SHOW VARIABLES LIKE ‘validate_password%’; |

### 비고

※ validate password 플러그인은 mysql v5.6 이상에서 제공

<!-- @block name=table cols=policy,description id=TB2 -->

| 패스워드 정책 |  |
|---|---|
| LOW | 8자리 이상 |
| MEDIUM | 영문자, 숫자, 특수문자 조합 8자리 이상 |
| STRONG | MEDIUM 정책 + dictionary 파일(금칙어) |

## GUIDE-MYS-003 타 사용자에 권한 부여 옵션 제한

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK3 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-MYS-003 |
| 플랫폼 | MY-SQL |
| 점검영역 | 계정 관리 |

### 항목 설명

WITH GRANT OPTION과 함께 권한을 받은 사용자는 해당 권한을 다른 사용자에게 부여할 수 있다. 그러므로 다른 Object의 사용 권한 부여는 DBA만 할 수 있도록 제한해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR3 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | grant_priv 권한이 적절한 사용자에게만 부여되어 있는 경우 |
| 취약 조건 | grant_priv 권한이 적절하지 않은 사용자에게 부여되어 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • grant_priv 권한을 부여 받은 사용자 조회 |
| 2 | 1) mysql> USE mysql; |
| 3 | 2) mysql> SELECT host, user, Grant_priv FROM user WHERE Grant_priv=’Y’; |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM3 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 불필요한 grant_priv 권한 제거 |
| 2 | 1) mysql> USE mysql; |
| 3 | 2) mysql> REVOKE grant option ON *.* FROM ‘권한 제거 사용자 계정명’@’접속 IP‘; |
| 4 | 3) mysql> FLUSH privileges; |

| 취약 조건 | DB사용자 계정 정보 테이블의 접근 권한이 적절한 사용자에게 부여되어 있지 않은 경우 |

## GUIDE-MYS-006 환경설정 파일 접근 권한

<!-- @block name=control keys=control_id,asset,category id=CK6 -->

MySQL 데이터 베이스의 주요 파일 중에 하나인 환경설정 파일에 비인가자가 접근하여 수정 및 삭제를 한다면 데이터베이스 운영에 장애가 발생할 수 있으며 계정 패스워드 정보 등의 중요한 정보가 유출될 수 있다.

| 취약 조건 | 환경설정 파일의 접근 권한이 640(-rw-r-----) 초과이면 양호 |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM6 -->

| 순서 | 절차 |
|---:|---|
| 1 | • mysql server configuration 파일 접근 권한 변경 |
| 2 | 1) # chmod 640 [mysql server configuration 파일 위치] |

## GUIDE-MYS-007 안전한 암호화 알고리즘 사용

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK7 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-MYS-007 |
| 플랫폼 | MY-SQL |
| 점검영역 | 보안 설정 |

### 항목 설명

SHA-1의 취약점이 발견됨에 따라 SHA-1은 더 이상 안전한 암호화 알고리즘이 아니다. 따라서 SHA-256 이상의 암호화 알고리즘을 사용해야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR7 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 해시 알고리즘 SHA-256 이상의 암호화 알고리즘을 사용하고 있는 경우 |
| 취약 조건 | 해시 알고리즘 SHA-256 미만의 암호화 알고리즘을 사용하고 있는 경우 |

### 진단 방법

<!-- @block name=check_steps method_no=1 cols=step,text id=MT7 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 안전한 패스워드 암호화 알고리즘 사용 |
| 2 | 1) mysql> SELECT host, user, plugin, authentication_string FROM user; |

### 조치 방법

<!-- @block name=remediation method_no=1 cols=step,text id=RM7 -->

| 순서 | 절차 |
|---:|---|
| 1 | • 안전한 패스워드 암호화 알고리즘 사용 |
| 2 | 1) mysql> ALTER user ‘사용자 계정 이름’@‘localhost’ IDENTIFIED WITH caching_sha2_password BY ‘패스워드’; |
| 3 | 2) mysql> FLUSH privileges; |

### 비고

※ mysql v8.0 이상부터 암호화 알고리즘으로 caching_sha2_password(SHA-256)가 적용됨

## GUIDE-MYS-009 최신 보안 패치 적용

### 점검 정보

<!-- @block name=control keys=control_id,asset,category id=CK9 -->

| 항목 | 내용 |
|---|---|
| 점검코드 | GUIDE-MYS-009 |
| 플랫폼 | MY-SQL |
| 점검영역 | 패치 및 로그 관리 |

### 항목 설명

데이터베이스의 주요 보안 패치 등을 설치하지 않은 경우, 버그 또는 알려진 취약점으로 인한 침해 사고가 발생할 수 있고 취약점을 이용하여 데이터베이스에 접근할 수 있다. 따라서 최신 보안패치 버전을 적용하여 데이터베이스의 보안성을 높여야 한다.

### 진단 기준

<!-- @block name=assessment_criteria keys=acceptable,vulnerable id=CR9 -->

| 판정 | 조건 |
|---|---|
| 양호 조건 | 최신 보안패치 버전이 적용되어 있으면 양호 |
| 취약 조건 | 최신 보안패치 버전이 적용되어 있지 않으면 취약 |
