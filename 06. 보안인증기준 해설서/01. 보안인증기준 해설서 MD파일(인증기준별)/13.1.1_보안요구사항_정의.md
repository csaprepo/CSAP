# 13.1.1 보안요구사항 정의

## 인증기준

신규 시스템 개발 및 기존 시스템 변경 시 정보보호 관련 법적 요구사항, 최신 보안취약점, 정보보호 기본요소(기밀성, 무결성, 가용성) 등을 고려하여 보안요구사항을 명확히 정의하고 이를 적용하여야 한다.

## 점검항목 해설

### 점검항목 1)

<!-- @block name=guidance requirement_no=1 cols=kind,text id=CM -->

| 구분 | 해설 |
|---|---|
| 본문 | 클라우드서비스를 개발하기 위하여 정보보호 관련 법적 요구사항, 최신 보안 취약점, 정보보호 기본요소(기밀성, 무결성, 가용성) 등을 고려한 보안요구사항을 정의하여 적용하여야 한다. |
| 세부 | 기밀성/무결성/가용성이 요구되는 데이터 분류 |
| 세부 | 데이터의 상태에 따른 기밀성/무결성 적용 여부(저장, 전송 등) |
| 세부 | 기밀성/무결성 적용 시 적용되는 암호 알고리즘의 적정성 여부 |
| 본문 | 정의된 보안요구사항을 반영하여 설계하고 개발하여야 한다. |
| 본문 | 신규 클라우드시스템 개발 및 기존 시스템 변경 시 아래의 정보를 참고하여 요구사항 정의부터 운영까지 일관성 있게 적용할 수 있도록 하여야 한다. |
| 세부 | 개인정보처리에 관련된 법적 요구사항 (예 : 개인정보취급자 권한 부여 기록, 접속기록, 암호화 대상 정보 등) |
| 세부 | 이용자 및 기관의 정보보호 요구사항 (예 : 접근권한 정의 및 통제 원칙, 암호화 대상 선정, 외주 위탁 시 보안요구사항 등) |
| 세부 | 정보보호 관련 기술적인 요구사항 등 (예 : 개발보안, 인증, 암호화 등) |

## 부적합 사례

<!-- @block name=findings cols=text id=NC -->

| 부적합 사례 |
|---|
| 사례 1 : 클라우드서비스 개발 시 정보보호 관련 법적 요구사항, 최신 보안 취약점, 정보보호 기본요소(기밀성, 무결성, 가용성) 등을 고려한 보안요구사항이 정의되어 있지 않거나, 적용되어 있지 않은 경우 |
| 사례 2 : 신규 클라우드시스템 개발 시 보안설계 기준(입력데이터 검증, 보안기능, 에러처리, 세션통제 등)을 정의하여 구현하도록 내부 정책이 수립되어 있으나 반영되어 있지 않은 경우 |
| 사례 3 : 이용자 및 기관의 정보보호 요구사항(접근권한 정의 및 통제 원칙, 암호화 대상 선정, 외주 위탁 시 보안요구사항 등)이 반영되어 있지 않은 경우 |
| 사례 4 : 신규 API 개발 시 보안요구사항 명세서 미작성, 신규 결제 API 프로젝트의 요구사항 명세서에 '인증', '인가', '입력값 검증', '암호화', '로깅' 등 보안요구사항 누락. 기능 요구사항만 15페이지 작성, 보안요구사항은 0건인 경우 |
