# 12.1.4 데이터 보호

## 인증기준

데이터에 대한 접근제어, 위변조 방지 등 데이터 처리에 대한 보호 기능을 이용자에게 제공하여야 한다.

## 점검항목 해설

### 점검항목 1)

<!-- @block name=guidance requirement_no=1 cols=kind,text id=CM -->

| 구분 | 해설 |
|---|---|
| 본문 | 모든 매체(스토리지, 백업 드라이브 등), 가상화 이미지, 스냅샷에 대해 엄격한 접근통제가 이루어져야 한다. |
| 세부 | 데이터에 대한 논리적 접근제어(가상화 이미지 및 스냅샷 등) |
| 세부 | ∙ 가상화 이미지 및 스냅샷에 대한 무단 변경을 탐지하기 위한 암호 체크섬 |
| 세부 | 시스템 자원, 데이터 자산, 백업 매체에 대한 물리적 접근제어 |
| 세부 | 데이터 입력, 처리, 통신, 전송, 출력, 저장 및 검색과 관련된 처리 및 전송 통제 |
| 세부 | 접근 가능한 인원을 최소화하고 접근권한 부여 등을 통해 접근통제 수행 |
| 세부 | 데이터에 접근할 수 있는 모든 경로 식별하여 접근통제 정책 적용 |
| 세부 | 데이터 접근은 역할기반 접근통제(RBAC)를 고려하여 최소 권한 원칙을 적용 |
| 본문 | 다음의 경우 데이터의 분실 방지 대책이 마련되어 있는지 확인하여야 한다. |
| 세부 | 저장 데이터 : 클라우드시스템 내 스토리지에 저장된 데이터 |
| 세부 | 전송 데이터 : 클라우드서비스 중 내·외부 네트워크에서 전송중인 이용자 데이터 |
| 본문 | 다수 이용자에게 서비스를 제공할 경우 데이터 개별 분리 (테넌트 분리, 테이블 분리, 물리적 분리 등)가 적용되어야 한다. |
| 세부 | ∙ NAS의 디렉토리 접근권한 방식 적용 불가 |
| 세부 | ∙ Object Storage를 통한 이용자별 접근통제 적용 가능 |
| 세부 | ∙ Block Storage를 통한 이용자별 스토리지 테넌트 분리 |
| 주의 | SaaS 서비스의 경우 이용자별 데이터는 최소한 테이블 단위 분리 보관 권고 |
| 본문 | SaaS의 경우 클라우드서비스 제공자는 중요 데이터(로그정보, 이용자 데이터 등)에 대한 접근을 통제하여야 한다. |
| 세부 | 접근 가능한 인원을 최소화하고 접근권한 부여 등을 통해 접근통제 수행 |
| 본문 | SaaS의 경우 클라우드서비스 제공자는 중요 데이터의 위변조를 방지하는 보호대책을 수립하여 적용하여야 한다. |
| 세부 | 데이터의 전송 및 저장 시 데이터의 위변조 방지를 위한 기술적 보호조치 적용 |
| 세부 | ∙ 암호 알고리즘, 해시 알고리즘 등을 이용한 위변조 방지기능 적용 |

## 부적합 사례

<!-- @block name=findings cols=text id=NC -->

| 부적합 사례 |
|---|
| 사례 1 : 중요 데이터(로그정보, 이용자 데이터 등)에 접근할 수 있는 사용자 권한을 업무 연관성이 없는 내부 임직원 또는 부서에 부여하고 있는 경우 |
| 사례 2 : 이용자의 동의 또는 요청에 의한 일시적 접근 및 법적으로 허용된 범위 외에 이용자 데이터에 접근한 접속 이력이 확인되는 경우 |
| 사례 3 : 이용자의 데이터를 분리하여 서비스를 제공하지 않아 A기관의 관리자가 B기관의 서비스 제공에 영향(데이터 수정, 삭제 등)을 미치는 경우 |
| 사례 4 : 스토리지 접근권한을 1년간 검토하지 않은 경우 |
| 사례 5 : 500개 객체 스토리지 버킷에 IAM 사용자 80명이 접근권한을 보유한 경우 |
| 사례 6 : 퇴사자 3명의 계정이 삭제되지 않고 여전히 전체 읽기/쓰기 권한을 유지하고 있으며 접근권한 최종 검토일로부터 13개월이 지난 경우 |
