# 13.2.2 개발과 운영환경 분리

## 인증기준

개발 및 시험 시스템은 운영시스템에 대한 비인가 접근 및 변경의 위험을 감소하기 위해 원칙적으로 분리하여야 한다. 단 분리하여 운영하기 어려운 경우 그 사유와 타당성을 검토하고 안전성 확보 방안을 마련하여야 한다.

## 점검항목 해설

### 점검항목 1)

<!-- @block name=guidance requirement_no=1 cols=kind,text id=CM -->

| 구분 | 해설 |
|---|---|
| 본문 | 클라우드서비스는 원칙적으로 개발/시험 환경과 운영환경이 분리되어야 한다. |
| 세부 | 개발 및 시험 시스템과 운영 시스템의 분리 |
| 세부 | 환경별 암호화 키 분리 및 별도의 VPC, 네임스페이스, 계정 사용 |
| 세부 | 운영 환경으로의 배포는 승인된 배포 절차를 통해서만 수행 |
| 본문 | 개발/시험 환경과 운영환경을 분리하기 어려운 경우 다음 사항을 포함한 보안대책을 수립한 후 적용하여야 한다. |
| 세부 | 개발/시험으로 인하여 영향을 받는 부분에 대한 범위 산정 |
| 세부 | 개발/시험의 오류로 인하여 발생할 수 있는 장애의 유형 및 복구 대책 |
| 세부 | 장애 발생 시 대응을 위한 상세한 시험절차(입력 매개변수 등 포함) 수립 |
| 세부 | 개발/시험 중 서비스 운영의 정상 여부를 지속적으로 모니터링하기 위한 대책 |
| 세부 | 운영환경에서 개발/시험을 수행하기 전에 정보보호 책임자 등으로부터의 승인 |
| 세부 | 운영데이터가 시험데이터로 사용되는 경우 운영데이터 보호를 위한 대책 |

## 부적합 사례

<!-- @block name=findings cols=text id=NC -->

| 부적합 사례 |
|---|
| 사례 1 : 클라우드서비스의 개발 및 시험 시스템을 운영시스템과 분리하지 않고 타당한 사유 또는 승인 없이 운영환경에서 개발을 수행하고 있는 경우 |
| 사례 2 : 클라우드서비스의 개발/시험 시스템이 별도로 구성되어 있으나, 개발환경에서 운영환경으로의 접근이 통제되지 않아 개발자들이 개발환경의 시스템을 경유하여 운영시스템에 불필요한 접근이 가능한 경우 |
| 사례 3 : 개발/시험이 완료된 결과를 운영환경으로 이관 시 책임자에 대한 승인 등 절차 없이 개발자가 직접 이관하고 있는 경우 |
| 사례 4 : 이관 중 발생 가능한 문제 및 대응방안, 이관 담당자 지정, 이관 방법 등이 포함된 절차가 수립되어 있지 않거나, 운영환경으로의 배포 승인 이력이 확인되지 않는 경우 |
| 사례 5 : 개발 환경에서 운영 데이터베이스에 직접 접근 가능, 개발자는 로컬 개발 환경에서 운영 데이터베이스 엔드포인트에 직접 연결 가능. 데이터베이스 접속 정보를 팀 공유 문서에 평문으로 기재하는 경우 |
