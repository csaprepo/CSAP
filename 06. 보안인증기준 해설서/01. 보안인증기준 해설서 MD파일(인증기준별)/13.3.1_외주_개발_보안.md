# 13.3.1 외주 개발 보안

## 인증기준

클라우드시스템 개발을 외주 위탁하는 경우 분석 및 설계단계에서 구현 및 이관까지의 준수해야 할 보안요구사항을 계약서에 명시하고 이행여부를 관리·감독하여야 한다.

운영체제에 소프트웨어를 안전하게 설치하기 위한 절차와 조치를 구현한다.

| 세부 | 컨테이너 이미지는 취약점 스캔(예: Trivy, Snyk 등)을 통과한 이미지만 배포 |
| 세부 | 소프트웨어 무결성 검증(예: 해시값, 디지털 서명) 또는 취약점 점검(이미지 실행 점검)을 수행 |
| 본문 | 클라우드시스템 개발 완료 후 보안요구사항 반영 여부, SW 보안취약점 점검 및 보완 여부, 개발자 계정 및 권한 삭제 여부 등을 확인한 후 검수 또는 인수하여야 한다. |

## 부적합 사례

<!-- @block name=findings cols=text id=NC -->

| 부적합 사례 |
|---|
| 사례 1 : 클라우드시스템 개발을 외주 위탁하는 경우 준수해야 할 보안요구사항이 포함된 위탁계약서가 없거나, 일부 중요 요구사항이 계약서에 포함되어 있지 않은 경우 |
| 사례 2 : 외주 위탁업체가 계약서에 명시된 보안요구사항을 준수하는지 여부를 확인하기 위한 점검 양식이 마련되어 있지 않거나, 점검 수행 이력이 확인되지 않는 경우 |
| 사례 3 : 외주 위탁업체를 통한 개발 완료 후 보안요구사항 반영 여부, 입력데이터 검증, 보안기능 등 SW 보안취약점 점검 및 보완 여부 등을 확인하기 위한 점검 양식이 마련되어 있지 않거나, 수행 이력이 확인되지 않는 경우 |
| 사례 4 : 컨테이너 이미지 취약점 검증 없이 배포, 퍼블릭 레지스트리에서 다운로드한 써드파티 이미지(nginx:latest, postgres:12)를 취약점 스캔 없이 운영 컨테이너 클러스터에 배포한 경우 |
| 사례 5 : 가상 서버 인스턴스 보안 설정 기준 미수립, 80개 가상 서버 인스턴스를 운영하나, '인스턴스 보안 설정 기준'(SSH 포트 변경, root 로그인 금지, 불필요한 서비스 비활성화 등)이 문서화되지 않고 담당자 개인 판단으로 설정하여 인스턴스마다 설정이 상이한 경우 |
