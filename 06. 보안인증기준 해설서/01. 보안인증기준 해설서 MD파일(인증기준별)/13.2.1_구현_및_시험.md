# 13.2.1 구현 및 시험

## 인증기준

안전한 코딩방법에 따라 클라우드컴퓨팅서비스를 구현하고, 분석 및 설계 과정에서 도출한 보안요구사항이 정보시스템에 적용되었는지 확인하기 위하여 시험을 수행하여야 한다.

## 점검목적

소프트웨어 개발 시 시큐어 코딩 원칙을 적용하여 개발 및 시험하는지 확인한다.

## 점검항목 해설

### 점검항목 1)

<!-- @block name=guidance requirement_no=1 cols=kind,text id=CM -->

| 구분 | 해설 |
|---|---|
| 본문 | 클라우드시스템을 안전하게 개발하기 위하여 안전한 코딩표준 및 규약에 따라 구현하여야 한다. |
| 세부 | 외부 환경 분석(법, 제도, 규정 등)을 통한 항목 식별 및 적용 |
| 세부 | 보안 기능 등을 결정하는 입력값에 대한 검증은 서버 측에서 수행 |
| 세부 | 기능에 대한 보안항목 식별 |
| 세부 | ∙ 사용자가 입력한 데이터의 유효성 확인 및 안전한 오류 처리 |
| 세부 | ∙ SQL 삽입 방지 |
| 세부 | ∙ 검증되지 않은 URL 리다이렉션 방지 |
| 세부 | ∙ 안전한 세션 관리 등 |
| 주의 | 참고: 소프트웨어 개발 보안 가이드(KISA), OWASP Secure Coding Practices, CERT Coding Standards 등 |

### 점검항목 2)

<!-- @block name=guidance requirement_no=2 cols=kind,text id=CM2 -->

| 구분 | 해설 |
|---|---|
| 본문 | 클라우드시스템 구현 완료 후 사전 정의된 보안요구사항이 설계된 대로 구현되었는지 확인하기 위하여, 시험 시나리오, 체크리스트 등을 작성하여 시험을 수행하여야 한다. |
| 세부 | 모든 보안요구사항이 구현되었는지 확인 |
| 본문 | 시험을 수행하기 위해 시험목적, 시험의 대상 기능, 시험환경(도구 포함), 시험절차 등이 포함된 시험계획을 수립하고, 시험계획에 따라 시험을 수행한 후 시험결과를 포함하여 문서로 기록하여야 한다. |

## 부적합 사례

<!-- @block name=findings cols=text id=NC -->

| 부적합 사례 |
|---|
| 사례 1 : 클라우드시스템을 안전하게 개발하기 위한 코딩표준이 마련되어 있으나, 입력데이터 검증, 보안기능, 에러처리, 세션관리 등 중요 보안항목을 반영하여 구현이 되지 않은 경우 |
| 사례 2 : 사전 정의된 보안요구사항이 설계된 대로 구현되었는지 확인하기 위해 시험계획을 수립하였으나 시험 수행 이력 및 결과가 포함되어 있는 증적이 확인되지 않는 경우 |
| 사례 3 : 구현 또는 시험 과정에서 알려진 기술적 취약성이 존재하는지 여부를 점검하지 않았거나 수행 이력이 없는 경우 |
| 사례 4 : 보안 SW개발 생명주기(S-SDLC) 프로세스가 없고, 연간 20개 이상의 신규 프로젝트를 진행하고 있으나 '보안 개발 생명주기' 프로세스가 없는 경우 |
| 사례 5 : 요구사항 단계부터 배포 단계까지 보안 활동(위협 모델링, 보안 코드 리뷰, 취약점 진단 등)이 정의되지 않은 경우 |
